# Zero-decay arithmetic and optional result snapshots

[Issue 20](https://github.com/eoinmurray/snnlab/issues/20) is addressed by the
0.12.0 fast default and public snapshot controls. Raw observations are retained
in [results.json](results.json). The [Modal run](https://modal.com/apps/me-93863/main/ap-lSFOu0hBwvM829LwS2ToBg)
used one NVIDIA L4, four CPU threads, PyTorch 2.10.0+cu128, snnTorch 0.9.4,
float32 and disabled TF32. The 0.11.0 baseline is commit
`8a601c7a77047542c9bc4a18e2b45677429beec4`.

## Protocol

Full runs now require independent training agreement in addition to shared-checkpoint agreement. Epoch losses and test loss must agree within `atol=1e-5, rtol=1e-5`; test accuracy must agree within 0.1 percentage point. Timings are excluded. The benchmark saves its diagnostic report and arrays before raising an error for failed agreement. The original retained 83.92% versus 77.67% result fails this gate; the regression asserts that it cannot be certified by the passing checkpoint checks. Reference-checkpoint-only runs do not assert independent training agreement because they do not train independently.

The focused regression in `tests/sim/test_snntorch_training_regression.py` separately runs 40 float32 clipped Adam updates with matched bias and surrogate backward operations, checking every gradient, updated parameter, Adam moment, class score and loss on CPU/CUDA. This diagnostic control intentionally matches operations; it does not certify the original unmatched benchmark. See [the investigation](investigation/README.md) for the numerical differences and the complete matched training result.

1. A matched 784 → 256 → 10 classifier uses 50 timesteps, synaptic decay 0.8,
   membrane decay 0.9, threshold 1, previous-membrane detached subtractive reset
   and the snnTorch fast-sigmoid derivative with slope 25. Four separate weight/bias
   projections supply instantaneous drive. SNNLab's built-in current-synapse
   time constant of 0.001 ms at dt=1 ms resolves to exactly zero decay. The custom
   neuron owns the actual synaptic filter. This is a dimensionless numerical
   classifier comparison, not a validation of biophysical units.
2. The snnTorch reference uses explicit matrix/bias operations with identical
   parameter layouts, rather than fused `nn.Linear`. Each condition receives
   identical initial or newly trained reference weights and fixed preencoded
   MNIST samples. Reference checkpoints are generated by this benchmark. Scores
   agree exactly and parameter gradients agree at `atol=1e-5`, `rtol=1e-4` for
   batches 128 and 32, at both checkpoint states. The largest discrepancy was
   `9.54e-7` initially and `2.98e-8` at the trained state for batch 128. The archived
   0.11.0 baseline and candidate strict path agree on the same comparison payloads.
3. Controlled timing uses three warmups and eleven repetitions, randomly
   interleaving conditions and forward/forward-backward/full-step operations.
   Device synchronization brackets timing; profiles are separate. Construction,
   encoding and weight restoration are outside these diagnostic intervals. A
   full step includes zeroing, cross-entropy, backward, norm clipping at 1 and
   warmed Adam. Each condition has its own optimizer; moments evolve while
   parameter values are restored outside timing. Forward/backward zeroing is
   performed outside its interval. These repetitions are not independent model
   or hardware replicates.
4. Complete runs cover all 60,000 MNIST training examples for two epochs and
   all 10,000 test examples. Batch size is 128, including partial final batches.
   All conditions share seeded ordering, Bernoulli encoding at feature × 0.25,
   initial parameters, Adam learning rate 0.001 and clipping. The run timer
   includes selection/encoding, training updates or test inference, but excludes
   dataset acquisition, common GPU data staging and model construction. Complete
   pipeline times have one observation per condition and are reported separately
   from repeated fixed-checkpoint timings.

## Measurements

Batch 128, newly trained common reference weights; median milliseconds:

| Condition | Forward | Forward/backward | Warmed full step |
| --- | ---: | ---: | ---: |
| snnTorch | 72.977 | 125.066 | 127.011 |
| SNNLab strict, full snapshots | 74.324 | 127.955 | 129.360 |
| SNNLab fast, full snapshots | 65.604 | 109.093 | 111.690 |
| SNNLab fast, outputs only | 65.749 | 109.232 | 110.970 |

1. Zero-decay specialization reduces the warmed step by 17.67 ms (13.7%).
   Multiplication counts fall from 1101 to 705 and additions from 501 to 301.
   Omitting unused snapshots reduces clone calls from 24 to 2; its additional
   timing benefit remains small and should not be generalized from one allocation.
2. Complete SNNLab training took 103.94 s in strict mode, 89.40 s in fast mode,
   and 88.01 s with fast output-only results. This is about 14.0% and 15.3% less
   training time respectively. Test inference took 4.85 s, 4.34 s and 4.18 s.
3. All three SNNLab variants produced identical reported epoch losses, test loss
   and accuracy: epoch losses 1.329271/0.677814, test loss 0.661028, accuracy 77.67%.
   The independently trained snnTorch model reached 83.92% and test loss 0.501698.
   Fixed-weight score/gradient agreement does not establish equivalent full
   training trajectories or accuracy across libraries. The source of this
   cross-library difference was not isolated here; it occurs under strict
   arithmetic too. These results establish the within-SNNLab optimization,
   not general library accuracy parity or superiority.
4. The original issue used PyTorch 2.11.0 and retained experiment checkpoints;
   this run uses the minimum supported PyTorch 2.10.0 and fresh checkpoints.
   Compare this report's controlled conditions, rather than treating its times
   as an exact replication of the original measurements.

## Numerical and persistence contracts

1. `projection_mode="fast"` is the default in training, inference and direct
   executor use. Exactly-zero built-in decay uses current drive directly; custom
   callbacks and nonzero recurrence remain unchanged. Strict mode retains IEEE
   multiplication by zero. NaN/infinite previous projection state can be cleared
   in fast mode, and its discarded zero backward edge no longer transmits
   nonfinite gradients. Signed zeros and absent-versus-zero leaf gradients can
   differ. There is no per-step finite scan for this optimization.
2. Public `retain_parameters`, `retain_final_state` and `retain_runtime_state`
   flags independently omit snapshots. Direct/inference defaults remain full;
   fresh-batch training/evaluation omit their unused forward snapshots internally.
   Complete optimizer checkpoints remain available. Request runtime snapshots
   when continuation is required.
3. Training protocols, inference retention identity and affected runtime-state
   compatibility record the arithmetic policy. Historical checkpoints and
   zero-decay continuation states require explicit strict execution; a requested
   mode switch is rejected. Omitted snapshots bind cache retention identity.
4. The isolated CPU suite passed 838 tests with 14 accelerator skips. Remote
   validation passed 76 checks including explicit CUDA cases, plus 20 separate
   CPU portability checks. Lint, both documentation base paths, documentation
   tests and the isolated wheel smoke passed. Numerical optimizer/continuation,
   nonfinite behavior, autapses, custom callbacks, recordings and cache-policy
   contracts are covered. Concurrent workspace conformance edits were excluded
   from the isolated release test tree.

## Reproduction

Install development dependencies and run on a CUDA machine:

```sh
uv run python benchmarks/zero_decay.py --output zero-decay.json
```

For the paired Modal run, install/authenticate the optional Modal CLI and set a
baseline directory containing the archived 0.11.0 `src/` tree:

```sh
SNNLAB_BASELINE_DIR=/path/to/baseline modal run benchmarks/zero_decay_modal.py
SNNLAB_BASELINE_DIR=/path/to/baseline modal run benchmarks/zero_decay_modal.py --only-tests --output zero-decay-tests.json
```

The runner mounts only explicit source/test/benchmark directories, uses a single
L4 and enforces a twenty-minute function limit. Retained Pinglab datasets or code
are not uploaded; public MNIST is acquired inside the container. The reference
libraries share the same allocation, and baseline diagnostics use the candidate's
exact initial/trained weight payloads.
