# SHD-shaped compilation investigation

Issue [21](https://github.com/eoinmurray/snnlab/issues/21) requires profiling before selecting timestep fusion. This harness compares the registered SHD derivative, its configurable built-in eager equivalent, and compiled built-in neuron kernels. Projection products and Python timestep scheduling remain eager. There is no timestep-block implementation here.

## Workload and scope

1. Synthetic Bernoulli inputs (probability 0.01, seed 43) have 700 channels, 1 ms timesteps and 1,000 timesteps per presentation. This exercises SHD dimensions without downloading SHD. Results cannot establish dataset accuracy or reproduce the motivating run exactly.
2. COBA has two 128-neuron feedforward layers. PING adds 32 inhibitory neurons per layer and fixed reciprocal excitatory/inhibitory loops delayed by one timestep. A 20-unit non-spiking leaky readout supplies its voltage trajectory; the external PyTorch loop uses `max(dim=0)` and cross entropy, followed by Adam. Feedforward/readout weights train; feedback remains fixed. Voltage gradient damping is explicitly 1.0; these graphs are probes rather than replicas of Pinglab's saved model.
3. The surrogate has slope `100/15`, gradient scale `1/100` and an exclusive threshold. The registered reference uses `(1/15)/(1+(100/15)*abs(v))**2` and the same exclusive spike convention. Existing built-in defaults stay inclusive with unit gradient scale.
4. Batches 32, 256 and 8 cover different full-batch sizes and a representative final partial batch. Each condition builds a fresh executor and records its first and second update separately, then three warmed forward, backward and complete-update samples. Cold update time includes compilation, allocation and optimizer initialization; it is not an isolated compiler duration. Complete updates include maximum-over-time reduction, loss, backward, Adam and constraint enforcement; input encoding/transfers are excluded.
5. CUDA synchronization surrounds each measured phase. Peak allocated memory includes warmup and the retained training graph, measured independently per condition. It excludes reserved memory and external processes. Modes run in fixed order on one H100 worker at a time; three samples are exploratory measurements, not a statistical speedup study.
6. CPU/CUDA operator profiles, Chrome traces and Python cProfile outputs come from separate updates at batch 32 over the first 128 timesteps. Profile counts/durations cover that bounded window, while throughput timings still cover all 1,000 steps. `aten::mm`/matrix-product rows identify projection costs; device events show kernel counts and costs; Python output shows scheduler/dispatch call costs. Host enqueue, CUDA execution and Python timings overlap and must not be summed or treated as an exact partition of wall time.

## Run

Run from the repository root in an environment containing SNNLab and PyTorch:

```sh
python benchmarks/shd-compilation/benchmark.py --kind coba --output /tmp/shd-coba
python benchmarks/shd-compilation/benchmark.py --kind ping --output /tmp/shd-ping
```

For a small CPU harness smoke test:

```sh
python benchmarks/shd-compilation/benchmark.py --device cpu --steps 8 --batches 2 --repeats 1 --output /tmp/shd-smoke
```

For Modal, use an authenticated Modal environment:

```sh
python -m modal run benchmarks/shd-compilation/modal_app.py
python benchmarks/shd-compilation/analyse.py
```

The launcher uploads `src/`, `tests/` and this benchmark directory to Modal, excluding Python caches and local results. It runs COBA then PING serially on H100 workers, downloads JSON measurements and compressed trace/profile artifacts into `results/`, and checks the focused regression suite on CUDA. Worker exceptions fail the launch explicitly; the launcher does not publish or deploy repository changes.

Small spiking COBA and delayed-PING graphs also compare registered/eager/compiled scores, voltage/spike trajectories, nonzero gradients, Adam parameters/moments and runtime continuation split at timestep 13. Their tolerance is `atol=rtol=2e-5`. These probes use stronger input weights to ensure both layers spike. They are correctness checks, not timings for the full benchmark graph.

## Profile evidence and next optimization

This table covers separate batch-32, 128-step forward/backward/Adam profiles. Device durations and host launch durations overlap. Matrix kernels are identified by CUDA kernel names containing `gemm`, `cutlass` or `cublas`, so this categorization is approximate and the raw operator/trace data remain authoritative.

| Graph | Mode | CUDA kernels | Summed kernel ms | Matrix kernel ms | Host launch API ms | Python forward self ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| COBA | custom | 23,311 | 32.407 | 5.411 | 92.784 | 45.212 |
| COBA | eager | 23,309 | 32.405 | 5.409 | 107.675 | 16.471 |
| COBA | compiled | 5,527 | 9.733 | 5.200 | 26.541 | 51.091 |
| PING | custom | 46,909 | 65.078 | 11.565 | 196.864 | 107.000 |
| PING | eager | 46,903 | 65.197 | 11.586 | 194.910 | 99.553 |
| PING | compiled | 11,360 | 19.962 | 11.164 | 51.042 | 111.114 |

1. Compilation cuts CUDA kernel count by roughly 76% in both graphs, while matrix-kernel duration changes little. Several thousand kernels remain even in the short compiled profile. This supports investigating dispatch and small-kernel overhead before attempting a different matrix-product algorithm.
2. Python `_forward` self time remains substantial after neuron compilation: approximately 51 ms for COBA and 111 ms for PING in the separate cProfile runs. This includes scheduler work and any tensor operations cProfile does not expose separately; it is not a pure measurement of Python scheduling alone. Compiled wrappers also add host calls. No additive partition of wall time or precise bottleneck percentage follows from these overlapping measurements.
3. The proposed next step is a prepared tensor-only timestep function combining projection drive/recurrence, incoming-current accumulation and ordered neuron/readout updates. Benchmark that first, then compare bounded 16/32/64-step blocks to amortize host dispatch. Keep temporal dependencies explicit: zero-delay edges consume the current step's earlier populations, and delayed reciprocal E/I loops consume their saved histories. Profiling supports this direction; it does not prove a speedup for the proposed blocks.
4. A block implementation must retain voltage-dependent COBA currents, refractory/autapse policy, forward and gradient continuity, readout conventions including maximum ties, and final partial blocks. Keep explicit eager fallback for registered callbacks, strict extension checks, recordings and interventions. Bind any new numerical/block policy to execution provenance and continuation/resume compatibility. No block path has been implemented or selected as a default in this pass.

## Validation and limitations

1. The local focused suite passed 115 tests, with 15 CUDA-dependent cases skipped locally. Actual CPU compiler probes for both spiking graphs passed.
2. The timed H100 worker passed 49 regression checks before measurement; the final source passed 51 checks in a separate H100 run, including runtime threshold policy/provenance. Small spiking COBA and delayed-PING probes passed registered/eager/compiled outputs, nonzero gradients, Adam parameters/moments and split runtime continuation at `atol=rtol=2e-5`.
3. The initial scaled detach proxy failed CUDA trajectory comparisons despite passing CPU checks. Non-default gradient scales now use an exact hard forward with a tensor-only explicit backward captured by the compiler. A direct compiled regression requires exact binary spikes and the expected derivative. Default unit-scale arithmetic stays unchanged.
4. The timed numerical source is pinned by hashes in each report. Final runtime-threshold compatibility and execution-provenance additions to `execution.py` followed that snapshot and passed a separate final CUDA regression check (51 passed). The other numerical source hashes match the final checkout.
5. The correctness probes use small 33-step circuits; full 1,000-step benchmark training trajectories and dataset accuracy were not equivalence-gated. Three timing samples, fixed mode order and one GPU do not justify statistical or universal speed claims. Further numerical and performance validation remains necessary for issue 21's fused-block acceptance criteria.
