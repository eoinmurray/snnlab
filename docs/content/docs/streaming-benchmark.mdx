---
title: "Streaming: Deadlines and Processing Costs"
description: Five-seed CPU timings and deadline misses for recurrent COBA networks processing one millisecond of simulation per callback.
---

This benchmark measures batch-one streaming inference with `prepare_stream()`
on four recurrent conductance-based networks, using **64, 128, 256 and 512 hidden
neurons**. Each callback advances **1 ms of model time**, with a new release and
deadline every **1 ms of wall time**. Five seeds contribute 5,000 windows each,
giving **25,000 measured windows per network size** on a macOS arm64 CPU.

Mean unpaced callback costs range from **63.5 to 113.5 µs**. The separate paced
passes record **3, 0, 7 and 2 deadline misses**, respectively. These are observed
host timings; low mean processing cost does not establish a hard deadline
guarantee.

**Measured Timings**

Unpaced wall times are equal-weight means ± sample SD across the five seed-level
means. Deadline counts and worst responses come from the separate paced pass.

| Hidden neurons | Full callback, µs | Prepared advance, µs | Deadline misses / 25,000 | Callback overruns / 25,000 | Worst response, ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 | 63.5 ± 1.3 | 55.0 ± 1.5 | 3 (0.012%) | 1 | 1.721 |
| 128 | 68.4 ± 1.6 | 60.0 ± 1.4 | 0 (0%) | 0 | 0.377 |
| 256 | 79.2 ± 2.0 | 70.7 ± 1.7 | 7 (0.028%) | 3 | 1.737 |
| 512 | 113.5 ± 6.2 | 104.6 ± 5.5 | 2 (0.008%) | 2 | 1.795 |

**Table legend**

1. **Full callback:** input generation, stream advance, host spike/event extraction and device completion. Excludes the wait for the next release, warmup and compilation.
2. **Prepared advance:** the `stream.advance()` portion of the unpaced callback pass. Internal phase bars use another instrumented pass, so their inclusive total need not equal this column. Phase clocks and completion fences affect timings; the compiled-block phase includes dispatch and completion waiting, not only numerical kernels.
3. **Deadline miss:** completion later than scheduled release plus 1 ms. **Callback overrun:** callback duration longer than 1 ms. A late start can cause a deadline miss even when the callback itself fits the budget. Releases stay anchored to one epoch; late callbacks catch up without dropping steps or moving deadlines.
4. **Worst response:** the largest individual release-to-completion duration across all five seeds. It is neither a mean nor a percentile.
5. **SD:** sample standard deviation across five seed-level measurements, using `ddof=1`. It is not SEM; the 25,000 windows are not independent seed replicates. Seeds change weights and inputs, and their variation also includes host scheduling effects.

Busy waiting occupies approximately one CPU thread even though inference takes
only a fraction of the 1 ms slot. These measurements exclude ROS scheduling,
communication, sensors and actuators. They do not establish performance in a VM,
on another processor or under deployment load. Zero observed misses at 128 hidden
neurons does not guarantee zero future misses.

**Numerical checks and reproduction**

Every seed and network size passed a 200-step comparison of prepared windows
against eager whole-sequence execution. The probe adds synchronous bursts at
window boundaries: spikes match exactly, and final state agrees with absolute
and relative tolerances of `3e-4`. Internal phase instrumentation also preserves
outputs and exported state exactly against an uninstrumented run. These checks
validate the measured execution paths for this workload.

Run from the repository root:

```sh
uv run python benchmarks/streaming/benchmark.py \
  --hidden-sizes 64 128 256 512 \
  --windows 5000 \
  --seeds 7 8 9 10 11
```

The command overwrites `benchmarks/streaming/results`. The post retains a separate
[JSON report](/streaming-benchmark/streaming-fd5b334b444c/report.json), including
configuration, numerical checks, per-seed summaries and all paced
release/start/finish timestamps. Its SHA-256 is
`fd5b334b444ca6d7763c1fd0c5a319e02ce4336afbbff21e22c4519c0d7b4dd9`.
The report does not record an execution date or source revision, so this command
describes the workload rather than a fully version-pinned reproduction.
