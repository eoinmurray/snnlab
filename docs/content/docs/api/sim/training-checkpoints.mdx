Import these types and functions from `snnlab.sim`. A training checkpoint retains learned weights, optimizer state and iteration metadata. It is distinct from an architecture bundle and from [runtime trajectory state](/api/sim/runtime-state).

## TrainingCheckpoint

```python
class TrainingCheckpoint:
    graph_digest: str
    training_digest: str
    completed_updates: int
    execution_protocol: Mapping[str, Any]
    initialization: Mapping[str, Any]
    parameters: dict[str, torch.Tensor]
    optimizer_state: dict[str, dict[str, Any]]
    rng_state: torch.Tensor
    rng_backend: str = "cpu"
    accelerator_rng_states: dict[str, torch.Tensor] = field(default_factory=dict)
    data_state: Mapping[str, Any] = field(default_factory=dict)
    selected_loss: float | None = None
    observation_state: Mapping[str, Any] | None = None
    selection_contract: Mapping[str, Any] | None = None
    selection_record: Mapping[str, Any] | None = None
    best_checkpoint: TrainingCheckpoint | None = None
    reporting_state: Mapping[str, Any] | None = None
```

`graph_digest` and `training_digest` identify the compiled graph and recipe. `completed_updates`, `data_state` and `execution_protocol` identify training progress and resolved inputs. `initialization` retains parameter realization metadata. Parameters use graph IDs; optimizer state is per-parameter tensor/JSON scalar state.

`rng_state` contains the CPU PyTorch generator state, while `rng_backend` and `accelerator_rng_states` identify accelerator streams. Optional observation, selection and reporting fields retain compatible audited histories, the selection contract, winning candidate and reporting progress. `best_checkpoint` retains the winner when the final training state differs from it. Treat returned checkpoints as training artifacts rather than inventing missing metadata for an old run.

## save_training_checkpoint

```python
def save_training_checkpoint(
    path: str | Path, checkpoint: TrainingCheckpoint
) -> Path: ...
```

Writes a directory containing `manifest.json` and `tensors.npz`, publishing individual files by replacement, and returns its `Path`. Use a dedicated destination; concurrent readers do not get a transactional directory swap. Tensor values and metadata are stored without pickle. Arbitrary Python optimizer objects, scheduler state and custom global optimizer state are not captured.

## load_training_checkpoint

```python
def load_training_checkpoint(
    path: str | Path, *, device: str | torch.device = "cpu"
) -> TrainingCheckpoint: ...
```

Reads supported schema versions 1–5, authenticates tensor payloads and metadata, moves parameters/optimizer tensors to `device`, and returns `TrainingCheckpoint`. Invalid schemas, digests, shapes, dtypes or audited metadata fail. The training handler additionally checks graph/recipe identity, input protocol, initialization and iterator coordinates before resuming.

```python
from snnlab.sim import load_training_checkpoint, save_training_checkpoint

# trained is the result of train(...).
save_training_checkpoint("final.checkpoint", trained.training_checkpoint)
checkpoint = load_training_checkpoint("final.checkpoint", device="cpu")
```

To resume built-in training, set `checkpoint` to the directory path. To run inference, the same directory supplies authenticated weights; optimizer/iterator state is not restored. A standalone PyTorch state dictionary is supported for inference but is not a built-in training-resume checkpoint.

## RNG capture and restore

```python
def capture_training_rng_state(
    device: str | torch.device,
) -> tuple[str, dict[str, torch.Tensor]]: ...


def restore_training_rng_state(
    checkpoint: TrainingCheckpoint, device: str | torch.device
) -> None: ...
```

`capture_training_rng_state` returns `(backend, accelerator_states)`. It does **not** return the CPU RNG state; manual checkpoint construction must capture that separately with `torch.get_rng_state()`. CUDA capture includes all available devices; MPS requires an available MPS backend. CPU returns `("cpu", {})`.

`restore_training_rng_state` mutates global CPU and matching accelerator PyTorch generators. It rejects a backend mismatch, missing states or changed CUDA topology. Normal built-in resume performs restoration itself; do not restore it merely to inspect a checkpoint. Python/NumPy/application RNGs are outside this checkpoint helper's contract.

## CheckpointSelection and SelectionMetric

```python
class SelectionMetric:
    kind: Literal["loss", "cross_entropy", "accuracy"]
    objective: int = 0
    direction: Literal["min", "max"] = "min"


class CheckpointSelection:
    split: Literal["train", "validation"] = "validation"
    cadence: Literal["completed_epoch"] = "completed_epoch"
    metric: SelectionMetric = SelectionMetric("cross_entropy")
    tie_break: Sequence[SelectionMetric] = ()
    include_initial: bool = False
    mode: Literal["epoch_metrics", "legacy_training_batch_loss", "none"] = (
        "epoch_metrics"
    )
```

Epoch selection evaluates a fixed state on the full train or validation split. Validation requires `ValidationSpec`; epoch selection requires positive epochs. `kind="loss"` selects by total weighted objective and regularizer loss, supports nonclassification recipes, and requires the default `objective=0` because it measures the entire recipe. Cross entropy and accuracy identify a classification objective by zero-based index. Cross entropy is unweighted and excludes regularizers; accuracy uses that objective's predictions. Each metric explicitly chooses `direction="min"` or `"max"`; accuracy does not automatically switch to maximization.

When `checkpoint_selection` is omitted and validation evaluation is enabled, training uses `CheckpointSelection(metric=SelectionMetric("loss"))`. An explicitly constructed `CheckpointSelection()` retains its cross-entropy default. Test data is never eligible for selection; final test evaluation uses the selected checkpoint, falling back to final weights when selection is disabled or unavailable.

Tie-break metrics are compared in order after exact ties; an exact tie retains the earliest candidate. `include_initial=True` admits epoch zero. A run ending before any eligible boundary can return `selected_checkpoint=None`.

| Method | Contract |
| --- | --- |
| `CheckpointSelection.disabled()` | Returns `mode="none"`; no selected candidate. |
| `CheckpointSelection.legacy_training_batch_loss()` | Historical lowest pre-update weighted batch loss paired with post-update weights. Also used when selection is omitted. |
| `to_dict()` / `from_dict(value)` | Round-trip JSON-compatible policies. |
| `validate(training, *, epochs, has_validation)` | Checks supported modes, splits, metrics and compatible classification objectives; raises on invalid policy. |
| `scores(metrics)` | Returns ordered finite scores from objective-indexed `cross_entropies` / `accuracies`; missing or nonfinite values fail. |
| `better(values, previous)` | Lexicographic comparison under declared directions; `previous=None` accepts the first candidate. |

Disabled and legacy modes reject extra epoch-metric settings. Resume authenticates selection/evaluation contracts and retains the best candidate across calls. See [request selection rules](/api/sim/execution-spec#checkpoint_selection) and [selection results](/api/sim/execution-result#checkpoint-selection).
