Import result types from `snnlab.sim.execution`. [ExecutionSpec](/api/sim/execution-spec) configures a run; these objects carry its results.

```python
from snnlab.sim.execution import ExecutionResult, NumpyExecutionResult
```

For concrete array layouts, units, file schemas and a runnable analysis workflow, see [Output and diagnostic data](/data-formats).

## Fields

| Attribute | Contents |
| --- | --- |
| `executor` | Execution backend label. |
| `outputs` | Named declared graph outputs. |
| `diagnostics` | Detached tensors for explicitly exposed signals; empty when disabled. |
| `parameters` | Named graph parameters; training returns detached final copies. |
| `gradients` | Named gradients from the final training update, when applicable. |
| `optimizer_state` | Named AdamW state from training. |
| `training_checkpoint` | Final in-memory training checkpoint. |
| `selected_checkpoint` | In-memory selected training checkpoint. |
| `final_state` | Named final dynamic tensors from graph forward execution. |
| `recorded_signals` | Explicit selected dense histories or sparse `(step, batch, cell)` events; empty when a sink consumes them. |
| `decisions` | Completed per-batch decision segments, with step bounds, duration and integer population/per-neuron spike counts. |
| `runtime_state` | Structured continuation state from graph forward execution. |
| `metrics` | Build/run timing, initialization/protocol and operation-specific evidence. |
| `model` | Built model where the handler supplies it. |

The result class uses empty mappings/`None` for absent data. Attributes are populated by the operation; do not assume every handler returns all state. For example, graph training returns final-update outputs/diagnostics and checkpoints but does not populate its result's `runtime_state` field.

## Epoch metrics

In dataset iteration mode (`epochs > 0`), `train` evaluates the complete training split at initialization and after each completed epoch. Supplying `validation` also evaluates the held-out split at those points. Results are returned as `result.metrics["epochs"]`:

| Field | Meaning |
| --- | --- |
| `epoch` | Number of completed epochs; `0` is the initial baseline. |
| `train_loss`, `validation_loss` | Sample-weighted mean total loss, including weighted objectives and regularizers. Validation fields appear only when validation data is supplied. |
| `train_accuracy`, `validation_accuracy` | Fraction correctly classified, from 0 to 1. Present when the recipe has exactly one classification objective (cross entropy or a custom objective registered with `classification=True`). |
| `train_components`, `validation_components` | Sample-weighted means by `objective[i]` and `regularizer[i]`. |
| `train_cross_entropies`, `validation_cross_entropies` | Unweighted cross-entropy by built-in `objective[i]`, excluding regularizers. |
| `train_accuracies`, `validation_accuracies` | Accuracy by `objective[i]`, including recipes with multiple objectives. |

Each evaluation uses fixed weights and minibatches bounded by `batch_size`. The final smaller batch is weighted by its actual sample count. Training samples are not shuffled during evaluation. `result.metrics["updates"]` retains the separate per-update losses measured before each optimizer step.

Resuming at an epoch boundary evaluates that starting boundary and subsequent completed epochs. Resuming partway through an epoch reports only subsequent completed epochs. An `updates` limit that stops partway through an epoch adds no partial-epoch measurement. With observations disabled, the returned history covers this invocation and previous history is not stored in the checkpoint. With observations enabled, history is retained and resumed as described below. Full-batch update mode without positive epochs returns an empty epoch history.

Epoch evaluations do not replace the final update's returned outputs or diagnostics. Explicit `checkpoint_selection` can select these evaluated states; otherwise selection retains historical update-loss behavior. Validation does not perform early stopping. Epoch evaluation adds forward passes over the splits; training itself remains inside one `train` call.

## Checkpoint selection

`result.training_checkpoint` contains the final training state. `result.selected_checkpoint` contains the winner under [ExecutionSpec.checkpoint_selection](/api/sim/execution-spec#checkpoint_selection), or `None` when no eligible candidate was evaluated. Their parameters can differ; inference uses whichever checkpoint directory you supply.

`selected_checkpoint.selection_record` and `result.metrics["selection_record"]` expose the winner's serialized `policy`, ordered metric `values`, absolute `update`, completed `epoch`, `phase` and `evaluation` identity. Epoch selection records unweighted cross-entropy and accuracy in policy order; exact ties retain the earliest winner. `phase` is `"initial"` or `"completed_epoch"`. The evaluation identity includes split protocol, seed, batch size, sample-weighted aggregation and content digests of resolved inputs and labels. `result.metrics["checkpoint_selection"]` contains the resolved contract.

The final checkpoint's `best_checkpoint` retains a complete separate winning snapshot (parameters, optimizer/RNG state, coordinates and optional observations), with no recursive nesting. Saving the final state writes its candidate to `selected/` and authenticates that candidate's manifest and tensors. Resuming the final checkpoint preserves the earlier winner; returning history remains governed by the independent observation setting.

`selected_loss` remains the historical training-batch-loss field. Epoch-selected candidates set it to `None`; read `selection_record` for their scores. The named legacy policy records `phase="legacy_training_batch_loss"` and explicitly labels pre-update loss versus post-update weights.

## Epoch observations

Supplying `ExecutionSpec.observations` adds an `observations` mapping to each epoch row while retaining the existing loss/accuracy fields:

```python
row = result.metrics["epochs"][-1]
rates = row["observations"]["validation"]["population_rates_hz"]
weight_norms = row["observations"]["parameters"]["l2_norm"]
gradients_before_clip = row["observations"]["gradients"]["pre_clip_l2_norm"]
reference = row["observations"]["probes"]["reference"]
```

| Entry | Semantics |
| --- | --- |
| `train`, `validation` | Requested population activity on the corresponding full evaluation split. Validation appears only when supplied. |
| `probes` | Separately named reference/validation draws, each recording `split`, `draw_id`, input protocol and evaluation seed. |
| `parameters.l2_norm` | Flattened stored parameter L2 norms at that fixed epoch state; `state` distinguishes initialization from a completed epoch. The `units` mapping records graph units; norms retain stored scaling. Non-finite requested norms raise an error. |
| `gradients.pre_clip_l2_norm`, `post_clip_l2_norm` | Arithmetic means of per-update flattened gradient L2 norms over that epoch, before and after the declared clipping step. They are not gradients recomputed on evaluation data. |

Each activity entry includes `duration_s` (per presentation), `sample_count`, `population_sizes`, `window="full_presentation"`, input protocol, split, evaluation seed and aggregation. Population rates divide total emitted spikes by samples × population size × physical presentation duration; the smaller final batch receives its actual sample weight. Mask inputs do not implicitly redefine this measurement window.

`output_activity[population]` records per-cell `spike_totals`, `silent_sample_fraction` (presentations with no spikes in that population), and `class_spike_shares` (each cell's fraction of total spikes). Cell index defines the class axis; class labels and scientific interpretation remain caller-owned. If no spikes occur, shares are `None` and `status="no_spikes"`, rather than fabricated zero probabilities. Counts come from the emitted output-neuron spikes, not weighted hidden-spike counts.

Gradient entries include the number of epoch `updates`, per-parameter `missing_updates` and `aggregation="mean_over_epoch_updates_with_gradient"`. Missing gradients are excluded from the mean. A parameter with no observed gradient returns `None`; initial measurements have `status="no_updates"`. Without clipping, before/after norms agree.

Epoch rows include absolute `update` and `phase="initial"` at epoch 0 or `"completed_epoch"` afterward. Completed history and partial-epoch gradient totals are stored in authenticated checkpoint observation metadata (schema version 3 for audited checkpoints). Resume returns the complete retained history without duplicate boundary rows, and adds a row only when another epoch completes. It rejects changed audit configuration or attempts to reconstruct history from an unaudited checkpoint. Ordinary histories remain invocation-local when observations are disabled.

These compact observations do not change final-update outputs, diagnostics or the configured checkpoint-selection policy. Pinglab's field aliases, plotting, audit thresholds and bank serialization remain outside snnlab.

## numpy

```python
data = result.numpy(batch=0)
spikes = data.outputs["spikes"]
voltages = data.diagnostics["e_voltage"]
time_ms = data.time_ms
```

`ExecutionResult.numpy(*, batch: int | None = None)` returns `NumpyExecutionResult` for plotting or analysis:

| Attribute | Contents |
| --- | --- |
| `outputs` | Named output NumPy arrays. |
| `diagnostics` | Named diagnostic NumPy arrays; empty when diagnostics were disabled. |
| `time_ms` | One-dimensional simulation time axis in milliseconds, or `None` when no execution occurred. |

The method detaches tensors, transfers them to CPU, and copies their NumPy arrays. Changing the arrays cannot modify the original tensors, and the original result retains its computation graphs. Conversion uses PyTorch's NumPy-supported dtypes.

Without `batch`, all batch items and tensor axes are preserved. Passing a non-negative integer selects that item and removes its batch axis. Selection uses the compiled signal shape: `(time, batch, cells)` becomes `(time, cells)`, while `(batch, classes)` becomes `(classes,)`. Signals without a batch axis are unchanged. Booleans and non-integer indices raise `TypeError`; negative or out-of-range indices raise `IndexError`. Selection requires metadata supplied by the graph executor, and is unavailable on a build-only or manually constructed result without that metadata.

`time_ms` comes from the effective execution timestep and step count, including timestep/duration overrides. It starts at zero for a fresh run; a resumed runtime trajectory starts at its absolute continuation step. Time-reduced outputs such as class scores do not have a time axis, even though `data.time_ms` still describes the run. Training converts its final-update outputs and diagnostics, with time referring to that update's input presentation.

Import `ExecutionResult` and `NumpyExecutionResult` from `snnlab.sim.execution` if needed for type annotations.

## Shapes and gradients

Shapes follow the declared graph signal, rather than one universal result layout. A population trace typically has `(time, batch, cells)` axes; time-reduced class scores have `(batch, classes)` axes. Keys in `outputs` are names from `net.output`; keys in `diagnostics` are names from `net.expose`.

Declared outputs always return, and direct graph forward outputs retain autograd. Diagnostics and continuation state are detached; `diagnostics=False` returns an empty diagnostic mapping. The built-in training result carries the last optimizer update's outputs, not an aggregate of all training presentations. Use `metrics` for epoch curves.

For a differentiable PyTorch loss use `result.outputs` tensors directly. Use `.numpy()` only for plotting or analysis. It converts outputs and diagnostics, not parameters, optimizer state or metrics.

## Constructor defaults

```python

    executor: ExecutorName
    outputs: dict[str, torch.Tensor] = field(default_factory=dict)
    diagnostics: dict[str, torch.Tensor] = field(default_factory=dict)
    parameters: dict[str, torch.Tensor] = field(default_factory=dict)
    gradients: dict[str, torch.Tensor] = field(default_factory=dict)
    optimizer_state: dict[str, Any] = field(default_factory=dict)
    training_checkpoint: TrainingCheckpoint | None = None
    selected_checkpoint: TrainingCheckpoint | None = None
    final_state: dict[str, torch.Tensor] = field(default_factory=dict)
    recorded_signals: dict[str, torch.Tensor] = {}

    runtime_state: GraphRuntimeState | None = None
    metrics: dict[str, Any] = field(default_factory=dict)
    model: nn.Module | None = None
```

```python
class NumpyExecutionResult:
    outputs: dict[str, np.ndarray]
    diagnostics: dict[str, np.ndarray]
    time_ms: np.ndarray | None
```

## Intervention provenance and replay cache checks

Graph simulation/inference returns `result.metrics["inference_interventions"]`, or `None` without interventions. It contains ordered `requested` and `resolved` metadata plus a `window` with absolute `start_step`, `steps_count`, `batch_size` and `dt_ms`. Replay rows include the canonical payload digest, representation and complete coverage; full payload tensors are not embedded in JSON. Stochastic rows include resolved seeds and add probabilities.

Generate an expected identity with [intervention_identity](/api/sim/execution-spec#replay-files-and-cache-checks) before reusing a cache, then pass it as `validate_inference_artifacts(..., expected_interventions=expected)`. This rejects a different replay or ordering and retains existing artifact-integrity checks. Explicit `None` requires an intervention-free cache. The keyword's omission preserves older integrity-only behavior; it does not authenticate the caller's entire inference request.

## Dataset batch encoding

Dataset requests retain `execution_protocol.batch_encoding` (`snnlab.batch-encoding/v1`) and selected source indices instead of retaining complete encoded inputs. Training `metrics["updates"]` rows include `encoding` with phase/epoch, original sample indices, draw seed, separate rate/spike seeds and encoder details. Categorical encoders also record the selected per-presentation rates. Epoch evaluation adds `train_encoding_draws` / `validation_encoding_draws` for provider inputs; totals and accuracies average across the declared draw set, and observation sample counts include all draw presentations.

Dataset inference returns full concatenated sample outputs and `metrics["encoding_batches"]`, using one initialized/checkpoint-loaded model. Explicit diagnostics are likewise concatenated; input batching does not imply bounded output retention. `runtime_state` is absent for multiple batches because each batch represents independent presentations; continuation is supported when the dataset fits in one batch. See [automatic batch encoding](/api/sim/execution-spec#automatic-batch-encoding) for defaults, exact replay and checkpoint compatibility.


## decisions

`result.decisions` contains completed records from an explicit [DecisionSegments policy](/api/sim/execution-spec#decisions). Partial segments remain in `runtime_state.segment_counts` with their cursor and full policy in `runtime_state.segment_state`; they are not prematurely reported at a call boundary. The result defaults to an empty list when no segments complete. Inference artifacts retain completed records in `metrics.json` and bind the policy and absolute execution window into the request digest. Ordinary output and diagnostic retention is unchanged.


## recorded_signals

Explicit [RecordingSpec selections](/api/sim/execution-spec#recording) return tensors keyed by graph signal ID in `recorded_signals`. Dense values have `(recorded_time, batch, selected_cells)` axes; sparse population spikes have `int64` rows `(absolute_step, batch, original_cell)`. Signal units and cell selections are retained in metrics. A sink consumes independent CPU blocks and leaves this mapping empty. `numpy()` continues to convert named outputs and diagnostics; convert selected recording tensors explicitly with `.numpy()` because sparse event axes differ from ordinary time-series axes.

Inference metrics expose automatic `online_reductions`, remaining `retained_signal_samples`, `measurement_complete` and digest-bound `inference_retention`. An explicit measurement window retains partial accumulators/cursor in runtime state, including portable save/load. With `retain_outputs=False`, `outputs` is empty; dataset inference also avoids collecting per-sample `final_state` tensors. Exposed diagnostics remain independent and explicitly controlled.
