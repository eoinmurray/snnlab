The simulator can run from a terminal as well as through the Python API. After [installing snnlab](/installation), use either entry point:

```sh
python -m snnlab.sim --help
snnsim --help
```

Both call the same implementation. In a project managed by uv, prefix commands with `uv run`. All execution commands require explicit `--bundle` and `--out-dir` paths.

## Commands and executors

| Command | Purpose |
| --- | --- |
| `sim` | Simulate an authored graph; optionally load checkpoint parameters. |
| `train` | Train using graph inputs and an authenticated bundle recipe. |

```sh
python -m snnlab.sim sim --help
python -m snnlab.sim train --help
```

The CLI and [ExecutionSpec](/api/sim/execution-spec) use graph execution. `--executor graph` is optional; no other executor is supported. Author the network with `snnlab.lang` and pass its compiled bundle. Graph execution requires exactly one input source: `--input-file`, `--event-file`, `--poisson-protocol` or `--dataset-file`. The available source flags depend on the command: generated Poisson and sparse event inputs are available on `sim`; `train` accepts dense replay or dataset snapshots.

## Complete graph simulation

Save this as `build_network.py` in your working directory. It compiles the same small excitatory network used in [Quickstart](/quickstart) and writes a bundle for the CLI:

```python
from snnlab import lang

net = lang.Network("cli-example", dt=0.1 * lang.ms)
inputs = net.input(
    "inputs", shape=("time", "batch", 4), signal_type="spikes", unit="spike"
)
cells = net.population("E", size=16, neuron=lang.COBA_LIF(tau_mem=20 * lang.ms))
net.connect(
    inputs,
    cells.excitatory,
    name="input_to_E",
    synapse=lang.AMPA(tau=2 * lang.ms),
    weight=lang.Uniform(0.1, 0.5),
    constraint=lang.NonNegative(),
)
net.output("spikes", cells.spikes)
net.expose(inputs, name="input_spikes")
net.expose(cells.voltage, name="e_voltage")
lang.compile(net, target="tools/snnsim").write("network.bundle")
```

Compile it, then generate 300 ms of input spikes at 80 Hz for one presentation:

```sh
python build_network.py
python -m snnlab.sim sim \
  --executor graph --bundle network.bundle \
  --poisson-protocol fixed-rate --input-rate 80 \
  --t-ms 300 --n-batch 1 --seed 17 --device cpu \
  --out-dir runs/poisson
```

The bundle supplies the timestep, topology and input dimensions. `--t-ms` sets duration in milliseconds; it must align with the bundle timestep. `--input-rate` is in Hz. For a categorical rate protocol, replace the protocol/rate flags with `--poisson-protocol categorical-rate --input-rates 5 25 80`; one listed rate is selected independently for each presentation. CLI Poisson generation requires exactly one declared spike input.

Graph runs write the following files, including after training:

| File | Contents |
| --- | --- |
| `outputs.npz` | Named graph outputs. |
| `recording.npz` | Exposed diagnostics; empty when disabled with `--no-diagnostics`. |
| `parameters.npz` | Named parameter arrays. |
| `metrics.json` | Execution metrics and input provenance; training also includes update/epoch metrics. |
| `inference-manifest.json` | Digests and array metadata for the saved artifacts. |

Inspect the simulation output:

```python
import numpy as np

with np.load("runs/poisson/outputs.npz", allow_pickle=False) as outputs:
    spikes = outputs["spikes"]
    print(spikes.shape)  # (3000, 1, 16): time, batch, cells
    print(int(spikes.sum()))
```

Graph execution saves arrays and metrics; it does not automatically produce figures. Use [snnlab.viz](/api/viz/plotting) to plot them.

## Replay and dataset inputs

For the bundle above, create a binary replay array and run it:

```python
import numpy as np

spikes = np.zeros((100, 1, 4), dtype=np.float32)
spikes[::10, 0, 0] = 1
np.savez("inputs.npz", inputs=spikes)
```

```sh
python -m snnlab.sim sim \
  --executor graph --bundle network.bundle --input-file inputs.npz \
  --device cpu --seed 17 --out-dir runs/replay
```

NPZ keys must match declared input IDs and cover every input exactly once. A NPY array can bind a graph with one input. Dense replay determines its own step and batch counts; the bundle supplies the timestep. The example runs for 10 ms. Sparse replay uses `--event-file events.npz`; see the [event binding contract](/api/sim/execution-spec#eventstreambinding) for coordinate rules.

Dataset snapshots use `--dataset-file snapshot.npz` together with `--dataset-encoder rate-poisson`, `prebinned-spikes` or `event-bin`. Supply `--input-dataset-id` and `--input-split` for provenance. Use `--dataset-input-id` to select the declared input; it is inferred only for a graph with one input. Feature and label keys default to `features` and `labels`; override them with `--dataset-feature-key` and `--dataset-label-key`. These commands consume local snapshots and do not download a dataset. See [DatasetSnapshotBinding](/api/sim/execution-spec#datasetsnapshotbinding) for shapes and encoder requirements.

## Graph training and checkpoints

Training requires a bundle with an authenticated training recipe, such as one compiled in the [Training example](/training). The simulation-only bundle above has no recipe. Given a training bundle, dense inputs and integer class targets, run:

```sh
python -m snnlab.sim train \
  --executor graph --bundle classifier.bundle \
  --input-file train-inputs.npz --target-file train-targets.npz \
  --epochs 3 --batch-size 32 --input-shuffle --seed 17 --device cpu \
  --save-final-checkpoint runs/train/final.checkpoint \
  --save-selected-checkpoint runs/train/selected.checkpoint \
  --out-dir runs/train
```

These filenames stand for prepared training data: input NPZ keys match graph input IDs, target NPZ keys match recipe target IDs, and each target has one integer label per sample. A target NPY is accepted when the recipe has one target. Alternatively, use a dataset snapshot with `--dataset-target-id` instead of separate input/target files.

The bundle recipe controls the optimizer, learning rate and trainable parameters. An omitted `--epochs` uses the recipe's epoch count; a positive count enables minibatch iteration. `--epochs 0` explicitly performs one full-batch update. The default selected checkpoint uses the lowest update loss.

Resume graph training by adding `--load-weights runs/train/final.checkpoint` and increasing the requested total epoch count. Keep the bundle, training data, seed and iteration settings compatible with the checkpoint. Load trained parameters for simulation with:

```sh
python -m snnlab.sim sim \
  --executor graph --bundle classifier.bundle \
  --input-file test-inputs.npz --load-weights runs/train/final.checkpoint \
  --device cpu --seed 17 --out-dir runs/inference
```

Graph simulation loads parameters without restoring the optimizer or training iterator. It does not require `--infer`, and does not automatically compute legacy test-set accuracy. See [checkpoint compatibility](/api/sim/execution-spec#checkpoint).

## Graph controls

| Flag | Behaviour |
| --- | --- |
| `--device auto`, `cpu`, `cuda`, `cuda:N`, `mps` | Select the execution device; default `auto`. |
| `--seed N` | Seed initialization and generated inputs. |
| `--no-diagnostics` | Disable exposed diagnostic collection; named outputs remain available. |
| `--save-runtime-state DIR` / `--load-runtime-state DIR` | Save or restore dynamic simulation state, including neuron, synapse and delay state. Separate from weight checkpoints. |
| `--scale-projection ID=FACTOR` | Scale a named projection for this simulation; repeatable. |
| `--intervention drop:POPULATION=PROBABILITY` | Drop emitted population spikes; probability must be between zero and one. |
| `--intervention add:POPULATION=RATE_HZ` | Add Poisson population spikes; repeatable interventions run in order. |
| `--intervention replay:POPULATION=PATH@sha256:FILE_DIGEST` | Replace emitted spikes with an authenticated dense/sparse replay payload. |
| `--inference-timestep-ms VALUE` | Recompile a graph copy at a new timestep with generated Poisson inputs; incompatible with runtime continuation. |

Projection scaling and interventions apply to `sim` and use exact graph IDs. The source bundle is not rewritten. See [inference options](/api/sim/execution-spec#inference_overrides) and [runtime continuation](/api/sim/execution-spec#runtime_state) for validation rules.

## Complete argument reference

These are all accepted execution arguments. Defaults are parser defaults; an omitted training epoch count uses the bundle recipe. Network structure, timestep, biophysics, initializers, optimizer settings and regularizers belong in the authored graph and training recipe.

| Argument | Commands | Default | Meaning |
| --- | --- | --- | --- |
| `--bundle` | `sim`, `train` | Unset | Load an authenticated snnlab.lang graph bundle. Training additionally requires an authenticated training.json. |
| `--executor` | `sim`, `train` | graph | Graph execution backend. |
| `--device` | `sim`, `train` | auto | Graph execution device: auto, cpu, cuda, cuda:N, or mps (default: auto). |
| `--diagnostics` / `--no-diagnostics` | `sim`, `train` | true | Return exposed graph diagnostics (default: enabled; use --no-diagnostics to disable). |
| `--load-runtime-state` | `sim`, `train` | Unset | Restore complete graph-executor dynamic state from a runtime-state directory. |
| `--save-runtime-state` | `sim`, `train` | Unset | Save complete graph-executor dynamic state to a runtime-state directory. |
| `--t-ms` | `sim`, `train` | 200.0 | Total simulation duration in ms (default: 200). Metrics are measured over the full trace; notebooks strip any startup transient in post. |
| `--input-rate` | `sim`, `train` | 25.0 | Baseline input rate in Hz (default: 25) |
| `--input-rates` | `sim`, `train` | Unset | Categorical Poisson rates in Hz. One rate is sampled uniformly and independently per image presentation. |
| `--out-dir` | `sim`, `train` | Unset | Output directory |
| `--seed` | `sim`, `train` | 0 | Graph initialization and input-encoding seed (default: 0). |
| `--max-samples` | `sim`, `train` | Unset | Limit a dataset snapshot to N samples. |
| `--load-weights` | `sim`, `train` | Unset | Graph checkpoint directory or PyTorch state dictionary for inference. |
| `--scale-projection` | `sim` | [] | Multiply a named graph projection for this inference request; repeatable. |
| `--measurement` | `sim` | Unset | Absolute start_step/end_step reduction window as JSON. |
| `--recording` | `sim` | Unset | Signal/cell selections and optional NPZ sink directory as JSON. |
| `--retain-outputs` / `--no-retain-outputs` | `sim` | true | Retain named output tensors; sinks receive outputs either way. |
| `--reset-voltage` | `sim` | [] | Selective leaky-integrator voltage reset as JSON; repeatable. |
| `--decisions` | `sim` | Unset | Decision segment boundaries and spike counts as JSON. |
| `--intervention` | `sim` | [] | Ordered spike intervention: drop:POPULATION=PROBABILITY, add:POPULATION=RATE_HZ or replay:POPULATION=PATH@sha256:FILE_DIGEST; repeatable. |
| `--inference-timestep-ms` | `sim` | Unset | Recompile an immutable graph copy at this inference timestep. |
| `--n-batch` | `sim` | 64 | Number of generated Poisson trials (default: 64). |
| `--input-file` | `sim`, `train` | Unset | Dense NPY/NPZ replay, bound by graph input id. |
| `--event-file` | `sim` | Unset | Sparse event-stream NPZ replay for graph execution. Coordinates are zero-based integer steps, batches, and channels. |
| `--dataset-file` | `sim`, `train` | Unset | Immutable NPZ dataset snapshot for graph execution. |
| `--dataset-encoder` | `sim`, `train` | Unset | Standard encoder applied to --dataset-file. |
| `--dataset-input-id` | `sim`, `train` | Unset | Named binding field; see ExecutionSpec. |
| `--dataset-target-id` | `sim`, `train` | Unset | Named binding field; see ExecutionSpec. |
| `--dataset-feature-key` | `sim`, `train` | features | Named binding field; see ExecutionSpec. |
| `--dataset-label-key` | `sim`, `train` | labels | Named binding field; see ExecutionSpec. |
| `--poisson-protocol` | `sim` | Unset | Generate graph-input Poisson spikes from --input-rate or --input-rates. |
| `--input-dataset-id` | `sim`, `train` | Unset | Stable dataset or snapshot identity recorded for a graph replay. |
| `--input-split` | `sim`, `train` | Unset | Dataset split recorded for a graph replay. |
| `--input-shuffle` / `--no-input-shuffle` | `sim`, `train` | Unset | Record whether the graph replay batch was shuffled (use --no-input-shuffle for false). |
| `--target-file` | `train` | Unset | Integer NPY/NPZ graph-training targets, bound by recipe target id. |
| `--save-final-checkpoint` | `train` | Unset | Write the final graph-training checkpoint directory. |
| `--checkpoint-selection` | `train` | Unset | Graph checkpoint selection policy as JSON (split, cadence, metric, tie_break, include_initial). |
| `--save-selected-checkpoint` | `train` | Unset | Write the selected graph-training checkpoint directory. |
| `--epochs` | `train` | Unset | Number of training epochs; defaults to the bundle recipe. |
| `--batch-size` | `train` | Unset | Mini-batch size for DataLoader. Default: 64 (from models.BATCH_SIZE). |

Legacy network flags, `--load-config`, `--infer`, `dump-weights` and `--executor legacy` are removed and produce argument errors. Historical configurations and results remain evidence; supply inputs and learned parameters through graph bindings/checkpoints for new execution.

## Checkpoint selection

Graph training accepts `--checkpoint-selection` as a JSON-serialized [CheckpointSelection](/api/sim/execution-spec#checkpoint_selection). For a graph request with training inputs and positive epochs, select the training split at completed epochs using:

```sh
--checkpoint-selection '{"split":"train","metric":{"kind":"cross_entropy","objective":0,"direction":"min"},"tie_break":[{"kind":"accuracy","objective":0,"direction":"max"}]}'
```

Supply this flag alongside the usual `train --executor graph --bundle ... --epochs ...` arguments. `--save-selected-checkpoint PATH` saves the winner; `--save-final-checkpoint PATH` saves the final state with its retained winner. Omitting the flag keeps the named legacy batch-loss policy. The current CLI has no held-out `ValidationSpec` binding interface; use the Python request API for validation-based selection. Malformed JSON or invalid policies fail rather than silently falling back.

## Population-spike replay

Create a dense or sparse replay with [the Python replay API](/api/sim/execution-spec#interventions), then write it with `save_spike_replay`. Pin its returned file digest and provide it in the ordered CLI intervention list:

```sh
--intervention 'replay:I=baseline.npz@sha256:YOUR_64_HEX_FILE_DIGEST'
```

Use this alongside `sim --executor graph --bundle ...` and the normal input/output arguments. The CLI constructs `ReplaySpikes("I", load_spike_replay(...))` in `ExecutionSpec.interventions`, verifies file bytes before loading arrays, and verifies canonical payload identity before stepping. Unknown targets, mismatched timestep/dimensions, incomplete coverage, corrupt files and missing digest pins fail. Repeated `--intervention` flags preserve order with drop/add interventions. Use absolute replay coordinates with `--load-runtime-state`; chunk boundaries do not restart replay. Relocating the same immutable file preserves its identity. Jitter and other stream transformations remain caller responsibilities.

## Automatic dataset batch encoding

`--dataset-file` automatically uses batchwise encoding for graph training and inference; there is no lazy/batchwise flag. `--batch-size` chooses the training batch size (default at most 32 in the Python request API when omitted). Dataset training without positive epochs runs one epoch. Source arrays are verified and memory-mapped once; only each selected batch is encoded. Training spike draws are fresh and evaluation draws are fixed; epoch/batch coordinates and separate stream identities support exact checkpoint resume.

For `--dataset-encoder rate-poisson`, use `--input-rate HZ` for fixed feature-scaled rates or `--input-rates 40 80 120` for a categorical maximum-pixel rate independently selected per presentation. `--t-ms` supplies presentation duration; normal sample cap/split/shuffle/tail behavior is retained. Both fixed and categorical rates use separate rate-selection and spike streams. Exact `prebinned-spikes` / `event-bin` replay remains supported.

Multiple explicitly seeded validation draws use `ValidationSpec.encoding_seeds` in the Python API; the CLI still has no held-out validation binding interface. Inference automatically uses batches of at most 32 through the CLI, loads its model/checkpoint once and concatenates requested outputs/diagnostics. Older eagerly encoded dataset checkpoints cannot resume under the new encoding protocol. See [request API](/api/sim/execution-spec#automatic-batch-encoding).


## Selective resets and decisions

Graph simulation/inference accepts repeatable `--reset-voltage JSON` and one `--decisions JSON`. They map directly to `ExecutionSpec.resets` and `ExecutionSpec.decisions`; see [boundary ownership and continuation rules](/api/sim/execution-spec#decisions).

```bash
python -m snnlab.sim sim --executor graph --bundle network.bundle \
  --input-file inputs.npy --out-dir decisions \
  --reset-voltage '{"population_id":"out","boundaries":{"steps":[0,200,400]},"value_mv":0.0}' \
  --decisions '{"boundaries":{"steps":[0,200,400]},"end_step":600,"population_totals":["E","I"],"output_spike_counts":["out"]}'
```

Use the usual direct dense/event/Poisson input flags for the stream. Boundary JSON also accepts `{"events":[{"step":0},{"step":200,"batches":[0]}]}` instead of `steps`. Inference `metrics.json` includes completed decisions and the resolved reset/segment policy. Use the existing runtime-state load/save flags for partial segments; provide the same full policy on each continued invocation. Legacy execution and independent dataset batches reject these fields.


## Bounded inference retention

Supported time reductions are optimized automatically. Graph simulation accepts `--measurement JSON` for an absolute reduction window, `--recording JSON` for selected signal/cell recordings and an optional NPZ sink directory, and `--no-retain-outputs` to consume outputs through a sink without accumulating them. Dense exposed diagnostics remain controlled by `--diagnostics` / `--no-diagnostics`.

```bash
python -m snnlab.sim sim --executor graph --bundle network.bundle \
  --input-file inputs.npy --out-dir inference \
  --no-diagnostics --no-retain-outputs \
  --measurement '{"start_step":0,"end_step":600}' \
  --recording '{"signals":[{"signal":"E.spikes","kind":"spike_events"},{"signal":"out.voltage","cells":[0,1]}],"directory":"recording-blocks"}'
```

The sink directory must be empty. Omit `directory` to retain selections in `recordings.npz`; optional recording `window` restricts selected history. Sparse event rows contain absolute timestep, global batch and original cell indices. Use the same measurement policy with runtime-state load/save on continued invocations and a separate sink directory per invocation. Dataset inference streams batchwise using one model load; output tensors/final states are not concatenated when retention is disabled. See [measurement](/api/sim/execution-spec#measurement), [recording](/api/sim/execution-spec#recording) and [output retention](/api/sim/execution-spec#retain_outputs) for partial results, compatibility and memory limits.
