---
title: Experiment Utilities
description: Read, validate, export and plot native evidence with explicit dataset identities.
---

These utilities consume SNNLab's native evidence without running a network. Dataset selection, preprocessing, topology, execution settings, diagnostic sample choice and figure composition stay in the experiment. Import the data APIs from `snnlab.sim` and the axes primitives from `snnlab.viz`.

The runnable offline example is [`examples/native-training/digits.py`](https://github.com/eoinmurray/snnlab/blob/main/examples/native-training/digits.py):

```sh
uv run python examples/native-training/digits.py --smoke --output /tmp/digits-evidence
```

Choose a fresh output directory. The example saves an explicit three-way digits split, trains an authored Bundle, selects by validation loss, evaluates the held-out test, records one explicitly selected test member and plots saved evidence. Its split policy is declared in the script; it does not reproduce another experiment's partition.

## TrainingHistory

```python
history = sim.TrainingHistory.read("metrics.json")
history = sim.TrainingHistory.from_metrics(result.metrics)

history.validate(
    expected_epochs=20,
    require_complete=True,
    selection=selection_policy,
    expected_examples={"test": 360},
    expected_encoding_draws={"test": (17,)},
)
curve = history.curve(metric="accuracy", split="validation", objective=0)
curves = history.curves(
    metrics=("loss", "accuracy"), splits=("train", "validation")
)
```

Reading copies the input mapping and validates available native evidence. `.validate(...)` raises `ValueError` for inconsistent evidence or unmet expectations. A caller-supplied `selection` must be a `CheckpointSelection` matching the stored policy. Reading does not certify that the underlying evaluation implementation was correct.

| Attribute | Contents |
| --- | --- |
| `epochs` | Tuple of `HistoryEpoch` records: `epoch`, named `splits`, optional `update`, and other native `metadata`. |
| `splits` | Available epoch split names, `train` and/or `validation`. |
| `selection` | Selected-checkpoint record, including `epoch`, `update`, policy and scores, or `None`. This is metadata, not checkpoint arrays. |
| `test` | Final held-out measurement and checkpoint/evaluation provenance, or `None`. |
| `performance` | Available requested/resolved performance metadata. |
| `timing` | Available native training phase/call/epoch timing, or `None` when disabled. |
| `coverage` | First/last observed epoch, contiguous coverage, recorded completion state, requested epochs, resume update and whether all epoch-selection candidates are available (`selection_verified`). Older artifacts can have unknown completion. |

Split records and native metadata are immutable mappings with attribute access. `curve()` returns a `MetricCurve` with independent `epochs`, `values`, `available` mask, per-point `measurement` semantics, split, metric and optional objective. `curves()` returns a mapping keyed by `(split, metric)`.

Absent measurements use NaN plus a false mask in the curve view; the underlying record stays absent. No epochs or evaluations are invented. Epoch-zero validation remains present when recorded; an online training baseline remains absent. Measurements retain `online_pre_update`, `fixed_weight_evaluation` or unknown historical semantics. Test evidence remains separate from curves.

Without `objective`, `loss` means total weighted loss. With an objective index it reads the native `components["objective[i]"]` value. Accuracy and cross entropy require an explicit objective when multiple values are available. Custom or regression losses may be negative; finite values are required, accuracy is bounded by `[0, 1]`, and cross entropy is nonnegative. Unavailable metrics remain unavailable.

Default validation checks increasing unique epochs, available metric domains/counts, candidate scores, selection direction/ties/initial eligibility and consistency with test provenance. Gaps and partial/resumed histories remain readable. `require_complete=True` requires all completed epochs through `expected_epochs` or the recorded requested epoch count; selection also requires all eligible candidates. With incomplete candidate evidence, validation can reject a winner worse than an available candidate but cannot certify a global winner. Example counts include repeated encoding draws: 100 original samples evaluated with two draws give `examples=200`.

Historical bare metrics JSON requires `TrainingHistory.read(path, legacy=True)`. An unknown schema is rejected even with that flag.

Legacy update-loss selection retains its native semantics: the score is a pre-update minibatch loss attached to post-update weights. Its recorded epoch is the presentation epoch ordinal (or absent in full-batch update mode), while a held-out test's epoch counts completed epochs at the checkpoint. The reader validates matching update/provenance records without treating that score as a fixed-weight epoch evaluation.

## NetworkSnapshot

```python
snapshot = sim.NetworkSnapshot.read("training/end")
snapshot = sim.NetworkSnapshot.from_snapshot(result.snapshots["end"])
snapshot.populations["E"].parameters["threshold_mv"].unit
snapshot.projections["input_to_E"].initializer
snapshot.parameter_info["input_to_E.weight"].runtime_shape
parameters = snapshot.load_parameters(names=("input_to_E.weight",))
snapshot.validate(verify_parameters=True)
```

`.read(path, parameters=False)` accepts a snapshot directory or `snapshot.json`. The default reads metadata without opening NPZ payloads or loading extension implementations. `parameters=True` eagerly verifies and caches all available parameter arrays. `from_snapshot(snapshot, parameters=False)` also defers copying captured tensors until requested; its source tensors remain mutable through the original `RunSnapshot`. `load_parameters(names=None)` verifies referenced storage and returns independent CPU tensors in their original dtype. Missing requested parameters raise an error; metadata-only snapshots return an empty mapping when all available parameters are requested.

| Attribute | Contents |
| --- | --- |
| `schema`, `snnlab_version`, `stage`, `graph_identity` | Source format, producer version, capture stage and graph digest. |
| `execution`, `training` | Effective execution settings and optional training recipe. |
| `populations` | ID-keyed population records with neuron definitions and `PhysicalParameter(value, unit)` values. Custom scalar configuration uses `config.<name>` keys; unspecified custom units stay unknown. |
| `projections` | ID-keyed source/target, delay, synapse parameters, authored/runtime matrix shape, initializer, scaling, constraints and trainable/frozen parameter names. |
| `parameter_info` | All declared parameters, units, initializers, scaling, constraints, resolved membership, initialization metadata and available storage descriptors. |

Authored matrix shape can differ from runtime storage orientation; both are retained. Initializer mean/std are requested settings. `initialization.statistics` describes realized weights **at initialization**, even in an end snapshot. Reading does not compute statistics of final weights. Membership uses captured runtime metadata when available, then the training recipe; absent historical evidence remains unknown. Snapshots retain schema `snnlab.run-snapshot/v1` with additive metadata and remain distinct from resumable checkpoints.

## RecordingData and NumPy conversion

```python
sample = result.numpy(batch=0)
spikes = sample.recorded_signals["E.spikes"]
recording = sample.recording
times = recording.info["E.spikes"].time_ms
cells = recording.info["E.spikes"].cell_ids
```

`sample.recorded_signals` is the same mapping as `sample.recording.signals`. `RecordingData(signals, info)` accepts NumPy arrays and a matching mapping of `SignalInfo` records. It copies arrays and validates metadata. `select_batch(index)` returns an independent selected recording. A previously selected recording rejects another selection.

`SignalInfo` exposes `axes`, `kind`, `unit`, original `cell_ids`, optional original `sample_ids`, actual `step_indices`, `dt_ms`, start/end step bounds, original `batch_size`, `source_dtype`, `array_dtype`, `conversion`, `selected_batch` and an optional reduction `measurement_window` retained from native sink blocks. Its `time_ms` property multiplies actual dense step coordinates by the timestep. Signals without time axes do not acquire a timeline. Sparse events retain integer `(step, batch, original_cell)` columns and their recording window; batch selection filters event coordinates without relabelling them.

NumPy conversion selects declared axes, copies requested retained signals to independent CPU arrays, and leaves original tensors and computation graphs intact. Empty signals and non-temporal signals remain supported. Float16/32/64 preserve their numeric dtype. Bfloat16 becomes float32 with explicit `conversion="bfloat16_to_float32"`; all finite values expand exactly. Artifact storage preserves original bfloat16 bits, including NaN payloads. Unsupported tensor dtypes raise rather than silently cast.

Windows and strided recordings use per-signal coordinates. `sample.time_ms` remains the existing full output timebase and must not be substituted for a selected recording's coordinates. Conversion cannot recover recordings consumed by a streaming sink or not retained during execution.

## Explicit exporters and schemas

```python
result.write_metrics("metrics.json", overwrite=False)
result.write_recording(
    "recording", signals=("E.spikes", "I.spikes"), batch=0,
    overwrite=False,
)
metrics = sim.read_metrics("metrics.json")
recording = sim.RecordingData.read("recording")
```

Both writers return their destination `Path`, publish staged output, and refuse existing destinations by default. `overwrite=True` explicitly replaces the destination artifact. Export does not execute a network, select a checkpoint, run analysis, retain extra signals or draw RNG. Metrics values must be JSON-compatible, optionally including NumPy scalars; non-finite and opaque values are rejected. Native performance and test/selection provenance remain intact.

Metrics use a JSON envelope with `schema="snnlab.metrics/v1"`, `snnlab_version` and the native `metrics` mapping. `read_metrics(path, legacy=False)` validates this envelope and returns its native mapping; `legacy=True` permits historical unversioned mappings.

Recordings reuse `snnlab.npz-recording-blocks/v1`: `manifest.jsonl` plus digest-identified `block-*.npz` files containing a `values` array. New blocks add explicit axes, step/sample coordinates, batch size and optional selected-batch identity to the existing metadata. Readers verify hashes, shapes, storage dtypes and block coordinates, joining only compatible time/batch tiles. Bfloat16 uses the existing `snnlab.bfloat16-bits/v1` uint16 representation. Historical dense/event blocks have defined native axes; historical output blocks without enough axis evidence are rejected. `RecordingData.read` also reads supported live `NPZRecordingSink` output. No Pingstore dependency is involved.

## DatasetSnapshot

```python
dataset = sim.DatasetSnapshot.from_partitions(
    dataset_id="digits",
    partitions={
        "train": sim.DatasetPartition(x_train, y_train, train_ids),
        "validation": sim.DatasetPartition(x_validation, y_validation, validation_ids),
        "test": sim.DatasetPartition(x_test, y_test, test_ids),
    },
    disjoint=("train", "validation", "test"),
    preprocessing={"operation": "divide", "divisor": 16},
)
dataset.write("dataset.npz")
saved = sim.DatasetSnapshot.read("dataset.npz")
binding = saved.binding(
    "train", input_id="pixels", target_id="class", encoder=encoder,
)
diagnostic = saved.binding(
    "test", sample_ids=(original_id,), input_id="pixels", encoder=encoder,
)
```

Partitions copy and retain the caller's feature/label shapes and dtypes, row order and integer or Unicode sample IDs. Features use a leading sample axis by default; declare `feature_sample_axis=1` for native `(time, samples, channels)` prebinned spikes. Labels retain a leading sample axis. Object arrays, duplicate identities and overlaps among explicitly declared disjoint partitions are rejected. The library does not normalize, transpose, shuffle or select rows implicitly. `preprocessing` and `provenance` record caller-owned descriptions; they do not apply transforms. `.counts` reports per-split original sample counts.

`write(path, overwrite=False)` creates one portable NPZ archive with schema `snnlab.dataset-snapshot/v1`. A uint8 UTF-8 JSON `__snnlab_manifest__` array describes named partitions, counts, array keys, shapes, dtypes, per-array SHA-256, disjointness, preprocessing and provenance. Readers validate all declared arrays and identities. Native bindings retain the digest of the complete archive and reject changes after binding.

Call `.read()` after writing to obtain a saved snapshot suitable for bindings. `.binding()` returns an existing `DatasetSnapshotBinding` with feature/label/identity keys resolved internally. An optional `sample_ids` sequence selects those existing members in the requested order and preserves original split provenance. It does not create independent test evidence. The native encoder pipeline still requires one-dimensional integer classification targets and its declared feature layout: rate-Poisson uses `(samples, channels)`, prebinned spikes use `(time, samples, channels)` with sample axis 1, and custom encoders receive canonical `features`, `labels` and `sample_ids` aliases as well as the original archive keys. Historical event NPZ bindings remain supported directly.

### Optional stratified splitting

```python
partitions = sim.stratified_split(
    features=x, labels=y, sample_ids=ids,
    fractions={"train": .7, "validation": .15, "test": .15},
    seed=17, policy="stratified-v1",
)
```

Splitting is a separate explicit operation. `stratified-v1` permutes each sorted label's rows using a local NumPy PCG64 generator, allocates rows per class by largest remainder, breaks equal remainders in split insertion order and emits each partition in original source order. Fractions must be finite, nonnegative and sum to one. Small classes may leave a split empty; no samples are duplicated. Each returned partition records this policy, seed, fractions and ordering in provenance. Supply existing partitions directly when adopting utilities in an established experiment; this algorithm does not promise scikit-learn's exact rows.

## Authored Bundle execution

`build`, `simulate` and `train` accept `bundle: lang.Bundle | str | Path`. Execution uses the authored object directly without a temporary save/load cycle. Saving and snapshots remain explicit:

```python
bundle.write("network.bundle", visualise=False)
result = sim.train(
    bundle=bundle, input_bindings=(train_binding,),
    validation=validation, test=test,
    epochs=epochs, batch_size=batch_size, seed=seed, device=device,
    performance=performance,
    snapshot=sim.SnapshotSpec(path="training", stage="both", parameters=True),
)
```

An explicit `graph` determines topology when both graph sources are supplied. Explicit `training` overrides the bundle recipe. Bundle-driven `train` loads its recipe when no override is supplied; `build` and `simulate` continue to require explicit `training` when trainable parameters are wanted. For the historical graph-plus-bundle training combination, a missing explicit recipe is loaded from the bundle and must authenticate the chosen graph. Prefer one graph source per call.

Disk loading verifies persisted digests. Mutable authored objects are copied and structurally validated; their existing training recipe must still reference the current graph digest, and assets are checked against manifest digests. Mutating a graph may therefore require recompiling its recipe. Existing path calls, extension resolution and execution/checkpoint identities remain supported. The in-memory source is described in snapshots by its graph identity.

## Epoch progress

```python
logger = sim.EpochLogger(
    metrics=("loss", "accuracy"), splits=("train", "validation"),
    labels={"validation": "val"}, precision=4, timing=True,
    stream=sys.stdout,
)
text = sim.format_epoch(report, precision=4)
# Pass logger as on_epoch_end=logger in the explicit train call.
```

`format_epoch` and `EpochLogger` share `metrics`, `splits`, `labels`, `precision`, `timing` and optional `objective`. Precision is an integer from 0 to 16. The formatter returns text; the logger writes one flushed line to its stream, defaulting to current stdout. Fields label online training and fixed-weight evaluation. Missing metrics, validation and disabled timing are omitted rather than replaced with zeros.

Only finalized `EpochReport` values are read. Existing callbacks, propagated exceptions and resume behaviour remain unchanged: only newly completed epochs produce progress lines.

## Axes plotting primitives

```python
raster_artists = viz.plot_raster(
    axis, recording, signal="E.spikes", batch=0,
    offset=100, color="tab:blue", label="E",
)
curve_artists = viz.plot_learning_curves(
    {"loss": loss_axis, "accuracy": accuracy_axis}, history,
    metrics=("loss", "accuracy"), splits=("train", "validation"),
    include_test=True,
)
```

`plot_raster` accepts `RecordingData` or a `NumpyExecutionResult`. Select a batch explicitly if one has not already been selected. The signal must have spike units and actual cell/time coordinates. `offset`, `color`, `label` and additional scatter keywords are explicit; population names do not determine scientific roles. It returns a Matplotlib `PathCollection`.

`plot_learning_curves` accepts caller-owned axes mapped by metric and a `TrainingHistory`. Optional `objective`, split-keyed `colors` and `labels` configure selection and appearance; additional keywords go to line plotting. Returned artist tuples are keyed by `(split, metric)`. Missing measurements, missing epochs and changes in measurement semantics break lines. Test measurements appear as separate scatter markers at their evaluated checkpoint epoch. These primitives do not smooth, normalize, create a layout, select a diagnostic sample, run a network or save files. The existing `viz.Recording`, composition tools and direct Matplotlib access remain available.
