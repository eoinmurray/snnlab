---
title: Compilation and Bundles
description: Compile, validate, save and load portable networks and recipes.
---

Import these functions and classes through `snnlab.lang`. Compilation validates and serializes the authoring graph. It does not train weights or run a simulation.

## compile

```python
def compile(
    network: Network,
    *,
    training: TrainSpec | None = None,
    target: str | None = None,
    assets: Mapping[str, str | Path] | None = None,
) -> Bundle: ...
```

| Argument | Meaning |
| --- | --- |
| `network` | The authored `Network`. |
| `training` | Optional [TrainSpec](/api/lang/training) recipe. |
| `target` | Optional backend capability target, such as `"tools/snnsim"`. |
| `assets` | Mapping of declared logical asset names to physical files. |

Graph and training validation errors raise `ValueError`. Backend capability diagnostics are retained in the bundle; inspect them before execution. Every declared asset needs a physical path, and undeclared or missing files are rejected. The manifest records digests, target, required capabilities and extension dependencies. Register importable callbacks or `module:function` references when authoring custom definitions. Their locations, units and optional exact package versions are recorded in the graph or recipe and covered by its digest. Bundle loading automatically imports the referenced external modules; no Python source or pickled callbacks are included in the bundle. See [Extensions](/api/lang/extensions).

## Bundle

```python
class Bundle:
    graph: dict[str, Any]
    training: dict[str, Any] | None
    manifest: dict[str, Any]
    diagnostics: list[Diagnostic]
    asset_sources: dict[str, Path] = field(default_factory=dict)
```

`graph` and `training` are serialized data mappings; optional recipes are `None` when absent. `manifest` describes integrity and capabilities. `diagnostics` contains compiler reports. `asset_sources` tracks physical files for writing.

```python
bundle = lang.compile(net, training=recipe, target="tools/snnsim")
path = bundle.write("network.bundle")
loaded = lang.load_bundle(path)
```

`Bundle.write(path, *, visualise=False)` returns a `Path` to a directory containing `graph.json`, optional `training.json`, `manifest.json`, bundled assets and `reports/summary.md`. With `visualise=True`, it also renders structural diagrams; Graphviz is required. Use a fresh destination when changing which optional recipes exist: writing does not clear an existing directory.

Saving a custom callback that cannot be resolved through an importable module raises `ValueError` before creating files. Move closures, lambdas and functions defined in `__main__` into a module first.

### Bundle.visualise

```python
bundle.visualise(path, *, view="circuit", scale=1, expand_groups=())
```

Renders one selected view to the given path and returns its `Path`. The suffix selects the output format; `expand_groups` applies to circuit/training views. This combines `lang.diagram` with `viz.render_diagram` without changing the bundle.

## migrate_refractory

```python
def migrate_refractory(graph: Mapping[str, Any]) -> dict[str, Any]: ...


old = lang.load_bundle("historical.bundle")
graph = lang.migrate_refractory(old.graph)
```

Returns a validated graph copy whose built-in neurons define refractory periods only as ms quantities. Authenticate saved bundles with `load_bundle` first. Historical counts become durations using the **original graph timestep**: twelve steps at 0.1 ms become 1.2 ms. If an archived COBA neuron relied on implicit rounded defaults, migration preserves its realised duration at that timestep. Conflicting duration/count fields fail.

Migration retains old COBA decrement-before-release scheduling through `refractory_timing="legacy_coba"`; other built-in models retain their following-step scheduling. New authoring always uses `"following_steps"`. Reauthor the network to adopt that common contract. Changing a migrated graph's timestep resolves its physical durations exactly and rejects non-divisible durations.

The source graph, bundle files and authenticated identity are unchanged. The migrated copy has a new digest; pass it through `ExecutionSpec.graph` for fresh execution. Checkpoints and runtime state are not converted or rebound. Keep them paired with the original graph. Do not replace `Bundle.graph` alone: the manifest and any training recipe authenticate its original digest. Built-in timestep inference overrides perform the same conversion before changing the timestep, preserving source checkpoint authentication.

## load_bundle

Loading verifies saved file digests before resolving external extension modules. Missing bundle paths raise `FileNotFoundError("bundle not found: ...")`; incomplete bundle directories raise `ValueError`. Referenced callbacks and declared exact package versions must be available in the current environment.

```python
def load_bundle(path: str | Path) -> Bundle: ...
```

Loads the directory, validates graph/recipe data and checks declared file digests. Missing or invalid files fail rather than silently recompiling the network. It returns a `Bundle` for inspection or reuse; supply its path to `ExecutionSpec.bundle` or its graph to `ExecutionSpec.graph`.

A bundle stores architecture, initializers and recipes. A training checkpoint stores learned parameters, optimizer state and resume metadata. Loading a bundle alone initializes fresh weights when executed; [Inference](/inference) also supplies a checkpoint. An external PyTorch model uses its own `state_dict`, as shown in [PyTorch Integration](/pytorch-integration).

## validate_graph

```python
def validate_graph(graph: Mapping[str, Any]) -> ValidationResult: ...
```

Returns `ValidationResult`, whose `.diagnostics` lists `Diagnostic(severity, code, message, subject=None)` records. `.errors` and `.warnings` filter diagnostics by severity; `.raise_for_errors()` raises on errors. This checks graph declarations; execution planning performs additional backend checks.

## validate_training

```python
def validate_training(
    graph: Mapping[str, Any], training: Mapping[str, Any]
) -> ValidationResult: ...
```

Import it directly from `snnlab.lang`. It validates a compiled recipe against the graph, including named parameters, objectives, targets, optimizer and surrogate declarations. Inspect the returned diagnostics or call `.raise_for_errors()`; successful structural validation does not establish backend support. `lang.compile` performs both graph and recipe validation automatically.

## Structural diagrams

```python
def diagram(
    bundle: Bundle, *, view: str = "circuit", expand_groups: Collection[str] = ()
) -> Diagram: ...
```

`lang.diagram` returns a renderer-neutral `viz.Diagram`. `view` accepts `"circuit"`, `"training"` or `"expanded"`. Circuit/training views collapse groups; `expand_groups` selectively expands known groups in those views. Unknown groups and unsupported view combinations raise `ValueError`. Expanded static views reject graphs with more than 120 projections plus operations. See [diagram rendering](/api/viz/diagrams).

## Diagnostic records and validation results

`Diagnostic` and `ValidationResult` are exported by `snnlab.lang`; `validate_graph` and `validate_training` return validation results.

```python
class Diagnostic:
    severity: str
    code: str
    message: str
    subject: str | None = None


class ValidationResult:
    diagnostics: list[Diagnostic] = field(default_factory=list)
```

`Diagnostic.line()` returns a formatted severity/code/message string, including the subject when present. `ValidationResult.errors` and `.warnings` are filtered diagnostic lists; `.raise_for_errors()` returns normally without errors and otherwise raises `ValueError`. A successful graph validation does not promise that every backend supports the graph; inspect bundle capability diagnostics and execution planning errors separately.
