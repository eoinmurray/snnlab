title: Extensions
description: Versioned Python registrations for custom dynamics, weights, operations, training and dataset encoders.
---

`snnlab.extensions` connects user-defined Python implementations to portable graph specifications. Register a stable name such as `my_lab.adaptive/v1` when authoring, then use it in a `lang.CustomNeuron` or another custom declaration. Callbacks can be importable functions or explicit `module:function` strings. Loading a saved bundle and graph simulation automatically resolve those references; the execution process needs no registration calls.

The public registry stays at `snnlab.extensions` and is shared by authoring and execution. Its built-in neuron contracts come from private `snnlab._shared`; importing the registry does not import the simulator or PyTorch. The runtime helpers in `snnlab.sim.graph.extensions` are internal implementation details, not another registry or public import location.

Bundles contain names, import references, units, dependency metadata and JSON configuration. Python source and pickled functions are never included. `graph["extensions"]` and `training["extensions"]` record each document's dependencies, covered by its digest; `manifest["extensions"]` lists the combined requirements. Referenced modules must be on Python's import path or installed in the execution environment. Loading imports these external modules and never downloads implementations. Changing an implementation's semantics requires a new versioned name; import references do not authenticate source contents.

```python
extensions.register_neuron(
    "my_lab.adaptive/v1",
    "my_lab.neurons:adaptive_step",
    initialize="my_lab.neurons:adaptive_initial_state",
    input_unit="nA",
    state_units={"adaptation": "nA"},
)
```

Keep the implementations as module functions, outside the bundle. Passing those imported functions directly records the same references automatically. Lambdas, closures, callable instances and functions defined in a script's `__main__` can be used in memory, but saving a bundle that uses them raises `ValueError` before writing files. Move them into an importable module first.

Missing modules, missing/non-callable attributes and conflicting cached definitions fail explicitly. A missing bundle path raises `FileNotFoundError("bundle not found: ...")`; the CLI exits with that message. Older bundles containing only names still require their original registrations because they provide no implementation locations. Recompile and save them to adopt automatic loading.

## Registration

Use the specialized registration functions below. Names must match a qualified identifier ending in `/v` and a positive version number. Duplicate category/name pairs raise `ValueError`; built-ins remain separate. `extensions.definitions(category=None)` returns registered immutable definition records for inspection.

All registrations accept optional `validate(config)`. It should raise `ValueError` for invalid configuration. Configuration must serialize as JSON; use numeric values or explicit unit/value mappings. Implement differentiable runtime functions using PyTorch operations, and use the supplied device/dtype when initializing tensors.

All registrations also accept `package=None, package_version=None`. `package` is the installed distribution name, which may differ from the import-module name. Supplying it records the installed version, or checks an explicitly supplied `package_version`. Every subsequent load checks the exact version, including when a definition is already cached. Missing packages and mismatches raise `ValueError`. Local project modules can omit this metadata; their compatibility is managed through the versioned definition name and the execution environment.

## Writing efficient PyTorch callbacks

Simulation compiles tensor updates by default through `Performance(compile_mode="default")`. Keep the ordinary importable Python callback signatures documented below; SNNLab prepares the compiled functions, so callbacks do not need `@torch.compile`. The graph-authoring `lang.compile(net)` is separate from this runtime tensor compilation. Use `performance=Performance(compile_mode=None)` on execution functions, `compile_mode=None` on `GraphExecutor`, or CLI `--compile-mode eager`, to debug an unsupported callback. See [Performance and Custom Components](/performance-and-custom-components) for the compatibility table, capture safety, mixed precision and measurement guidance.

- Operate on whole tensors with PyTorch broadcasting, reductions and elementwise operations. A neuron step receives all `(batch, cells)` values together; a synapse step receives a weight-projected drive for all target cells. Avoid Python loops over cells, samples or edges.
- Keep tensor shapes, state keys, dtypes and devices stable. Return new state tensors without modifying the previous state in place. Use `zeros_like`, `full_like` or the supplied initialization device/dtype rather than creating CPU tensors during an accelerator update.
- Keep tensor data on the device. Avoid `.item()`, `float(tensor)`, `bool(tensor)`, `.tolist()`, `.cpu()`, `.numpy()` and rebuilding tensors from Python lists in the update. Host reads can synchronize GPUs and prevent graph capture.
- Use `torch.where`, masks and other tensor expressions for decisions based on tensor values. An `if` on fixed JSON configuration is usually traceable; an `if` on `voltage.any()` is data-dependent Python control flow. Both branches of `torch.where` are evaluated, so make each numerically safe, for example by clamping a denominator before division.
- Put configuration checks in `validate(config)`, outside numerical updates. Fixed scalar math such as `math.exp(-context.dt_ms / config["tau_ms"])` can specialize during tracing. Avoid logging, file access, registry calls, global mutable state and random draws from Python/NumPy inside compiled updates.
- Preserve autograd for dynamics and operations. Use `context.spike` for the configured surrogate; avoid detaching state or converting it back into `torch.tensor(...)`. Keep trajectory state in the supplied mapping so saved continuation reproduces the dynamics.

Compilation prepares separate kernels per population/projection and captures their configuration. Reuse the executor across calls; new batch shapes, devices, dtypes or gradient modes can trigger compilation again. Measure the first call separately from repeated calls, and synchronize the accelerator when measuring completed work. Compilation can fuse elementwise work, but it does not compile the entire timestep loop or guarantee faster short runs.

Test new callbacks with `extension_validation="strict"`, comparing compiled and eager outputs, gradients and split-run continuation with appropriate floating-point tolerances. Strict value scans remain outside compiled updates and can synchronize GPUs. Structural mode is the default for steady execution and retains shape/device/dtype/state-key checks. Registered custom surrogates in strict mode keep an eager spike/autograd boundary for derivative checks; their derivative calculations still compile separately. Compiler errors are surfaced; opt out explicitly while adapting unsupported code.

Weight/state initializers run eagerly during setup, preserving seeded initialization. Repeated weight constraints and custom graph operations compile; their validation remains outside the compiled calculation. Training objectives, regularizers, optimizer factories, dataset encoders and scalar weight-modulation callbacks are outside this compilation scope. Their code should still use vectorized PyTorch whenever it processes tensors.

## Neurons

```python
def register_neuron(
    name,
    step,
    *,
    initialize,
    input_unit="nA",
    state_units=None,
    validate=None,
    package=None,
    package_version=None,
): ...
```

`initialize(StateContext)` returns a mapping containing `voltage` and any additional tensor state. `refractory` defaults to a zero-valued integer tensor. `step(NeuronContext)` returns `(new_state, spikes)`. Return a new state mapping and avoid mutating previous tensors in place. State keys, tensor shapes and dtypes must remain stable during execution; spikes must be binary and have `(batch, cells)` shape.

`input_unit` is `"nA"` for current or `"uS"` for conductance. `state_units` maps additional state names to units; these exposed ports must have `(batch, cells)` floating tensors. Declare a diagnostic with `net.expose(cells.state("adaptation"), name="adaptation")`. The standard voltage/spikes/refractory ports cannot be redeclared.

```python
class StateContext:
    shape: tuple[int, int]
    device: Any
    dtype: Any
    dt_ms: float
    config: Mapping[str, Any]
```
```python
class NeuronContext:
    state: Mapping[str, Any]
    excitatory: Any
    inhibitory: Any
    dt_ms: float
    config: Mapping[str, Any]
    spike: Callable[[Any], Any]
```

`NeuronContext.spike(value)` emits hard threshold spikes with the configured backward surrogate. Custom neurons choose their integration, reset and refractory behaviour; receiving a refractory state tensor does not implement those dynamics automatically. Extra hidden state can have other fixed shapes and dtypes, but must remain finite and on the execution device. All state is detached and saved at continuation boundaries.

```python
neuron = lang.CustomNeuron("my_lab.adaptive/v1", tau_ms=20.0)
```

The existing `step(context)` interface compiles directly when the body follows the [efficient callback guidance](#writing-efficient-pytorch-callbacks). Preserve auxiliary state with `{**context.state, "voltage": next_voltage, ...}`. See [Customisation](/custom-neurons-and-synapses) for a complete adaptive neuron definition and its response plots.

## Synapses

```python
def register_synapse(
    name,
    step,
    *,
    initialize=None,
    output_unit="nA",
    input_unit=None,
    state_units=None,
    validate=None,
    package=None,
    package_version=None,
): ...
```
```python
class SynapseContext:
    state: Mapping[str, Any]
    drive: Any
    dt_ms: float
    config: Mapping[str, Any]
```

`initialize(StateContext)` optionally returns synapse state with a required `value` tensor. Without it, `value` starts at zero. `step(SynapseContext)` receives delayed source activity already multiplied by the projection weights as `drive`. Return the complete updated state mapping, including `value`, which is added to the target's excitatory or inhibitory input.

`output_unit` is `"nA"` or `"uS"`; it must match the target neuron. Additional `state_units` expose diagnostic ports through `projection.state(name)`. The standard `value`, `current` and `conductance` names are reserved. Arbitrary auxiliary tensor state survives continuation; built-in delay routing and graph topology remain in effect.

```python
synapse = lang.CustomSynapse("my_lab.synapse/v1", tau_ms=5.0)
```

A vectorized step for an exponential custom synapse can be written as:

```python
import math

def exponential_step(context):
    decay = math.exp(-context.dt_ms / context.config["tau_ms"])
    previous = context.state["value"]
    drive = context.drive.to(previous.dtype)
    return {**context.state, "value": previous * decay + drive}
```

Register this importable function with `register_synapse`; omitting `initialize` supplies the zero-valued `value` state. There is no per-cell loop or host read, and the fixed scalar decay can specialize during compilation. The drive cast preserves state dtype under autocast. The weighted drive is already supplied: do not multiply weights or loop over source edges again. The [runnable customisation example](/custom-neurons-and-synapses) includes a state initializer, configuration validation and capture-safe registration.

### Voltage-driven graded connections

A custom synapse can declare `input_unit="mV"` and receive `pre.voltage` or a declared `pre.state("activation")` port with matching units. Explicit drive units may be `"1"`, `"mV"`, `"nA"` or `"uS"`. Projection weights then have unit `"1"`; `output_unit` still specifies the current or conductance delivered to the postsynaptic neuron. Omitting `input_unit` preserves the historical spike/external-input contract, including weight units and saved bundle descriptors.

```python
import torch
from snnlab import extensions, lang

def graded_init(context):
    gate = torch.full(context.shape, -60.0,
                      device=context.device, dtype=context.dtype)
    return {"gate": gate, "value": torch.zeros_like(gate)}

def graded_step(context):
    gate = context.state["gate"]
    gate = gate + context.dt_ms / 2.0 * (context.drive - gate)
    conductance = 0.04 * torch.sigmoid(0.3 * (gate + 50.0))
    return {"gate": gate, "value": conductance}

extensions.register_synapse(
    "my_lab.graded/v1", graded_step, initialize=graded_init,
    input_unit="mV", output_unit="uS", state_units={"gate": "mV"},
)
edge = net.connect(
    pre.voltage, post.inhibitory, name="graded_inhibition",
    synapse=lang.CustomSynapse("my_lab.graded/v1"),
    weight=lang.Constant(1.0), initialization_scaling="direct",
    connection="recurrent",
)
net.output("gate", edge.state("gate"))
net.output("conductance", edge.conductance)
net.output("voltage", post.voltage)
```

The constants above use milliseconds, millivolts and microsiemens. The gate filters voltage with a 2 ms time constant, and maximum output conductance is 0.04 uS. The postsynaptic conductance-based neuron converts this output into current using its reversal potential and its own beginning-of-step voltage. A custom target neuron chooses its own reversal potential.

1. All continuous population sources sample beginning-of-step state, after any explicit voltage reset and before any membrane advances. Reciprocal edges therefore read the same time origin regardless of population order. Gates update from that snapshot and their new outputs contribute to the current membrane step. Zero-delay continuous edges may form cycles, including with the default `connection="feedforward"`; spike feedforward scheduling is unchanged.
2. A custom state source samples the previous completed state, including its initializer on the first step. It does **not** expose an activation newly computed during this step. Models needing a gate calculated from old voltage should implement that gate in the synapse callback. Newly updated activation sampling is unsupported.
3. `drive = sampled_source @ weight` occurs **before** the nonlinear callback, including the usual initialization scaling, autapse mask and optional gain modulation. There is one gate per target cell, filtering the weighted aggregate; this is not a separate gate per source-target pair. Use `initialization_scaling="direct"` for literal weights. Put maximum conductance/output scaling in the callback; multiplying voltage before a sigmoid changes its activation curve.
4. An explicit delay of `d * dt` adds `d` whole steps to the beginning-of-step sample. For `d=0` the callback reads the current step's initial state; for `d=1` it reads the preceding step's initial state. Prehistory holds each source's initialized value. Delayed source history and synapse gates survive saved runtime continuation. Recurrent continuous edges add no implicit delay; existing spike edges retain their causal delay rules. The `feedback` connection label still requires an explicit positive delay.
5. Direct voltage and declared neuron state ports are supported. Pre-reset voltage, projection outputs and operation chains over continuous population signals are unsupported projection sources. Source units must match `input_unit`; weights must be dimensionless and synapse output units must match the target neuron input units.

The [reciprocal graded-synapse example](https://github.com/eoinmurray/snnlab/tree/main/examples/graded-synapses) compares two passive membranes with an independent gate-first NumPy Euler implementation in CPU float64 and exports gate, conductance and voltage traces. It demonstrates reusable graph coupling; it does not reproduce the intrinsic neuron dynamics of the Neuromorphic Toolbox half-centre oscillator.

## Initializers and constraints

```python
def register_initializer(
    name, function, *, validate=None, package=None, package_version=None
): ...
```
```python
def register_constraint(
    name, function, *, validate=None, package=None, package_version=None
): ...
```

Initializer callback: `function(shape, config, *, device, dtype) -> Tensor`. Return finite values with the exact requested shape/device/dtype. Use PyTorch's seeded generator for reproducible draws, rather than hidden random state. Projection runtime shape is `(source, target)`; ordinary custom-operation parameters retain their declared shape.

Constraint callback: `function(parameter, config) -> Tensor`. Return the constrained tensor with unchanged shape/device/dtype. Constraints apply after initialization and the selected scaling policy, and after built-in training optimizer steps. An external PyTorch loop should call `module.enforce_constraints()` after its optimizer step. A masking constraint can enforce persistent zero connections; execution still uses dense matrices. Initializers run eagerly at construction, while constraints compile for repeated post-update use. Vectorize both across the full weight tensor, allocate directly with the requested device/dtype, and avoid scalar loops over connections. See [efficient custom weights](/weights#efficient-custom-initializers-and-constraints) for examples.

```python
initializer = lang.CustomInitializer("my_lab.distribution/v1", scale=1.0)
constraint = lang.CustomConstraint("my_lab.mask/v1", mask=[[1, 0], [0, 1]])
```

## Operations and readouts

```python
def register_operation(
    name, function, *, validate=None, package=None, package_version=None
): ...
```
```python
def custom_operation(
    definition: str,
    sources,
    *,
    name: str,
    shape,
    unit: str,
    parameters=(),
    signal_type="continuous",
    **config,
) -> Signal: ...
```

Callback: `function(sources, parameters, config) -> Tensor`. `sources` is a tuple of input tensors; `parameters` maps declared graph parameter IDs to live tensors. Return the declared output shape on the execution device/dtype, retaining autograd. Explicitly list any trainable parameters through `parameters=(ref, ...)` and select them in the training recipe. Captured Python modules or tensors are not automatically registered model parameters.

Custom readouts can be operations, explicit graph populations, or ordinary external PyTorch layers. Custom architecture builders are normal Python functions that call the Network methods; they expand before serialization. This API does not add arbitrary connection routing or sparse storage backends.

## Objectives and regularizers

```python
def register_objective(
    name,
    function,
    *,
    classification=False,
    validate=None,
    package=None,
    package_version=None,
): ...
```
```python
def register_regularizer(
    name, function, *, validate=None, package=None, package_version=None
): ...
```

Objective callback: `function(prediction, target, config) -> scalar Tensor`. Use `lang.CustomObjective(definition, prediction=signal, target="name", weight=1.0, **config)`. Non-classification objectives accept finite real target tensors with a leading sample axis, including multidimensional regression targets. `classification=True` requires one-dimensional integer labels and enables argmax accuracy metrics.

Regularizer callback: `function(signals, duration_s, config) -> scalar Tensor`. Use `lang.CustomRegularizer(definition, signals=(signal, ...), strength=..., **config)`. Signals are supplied even when diagnostics are disabled. The executor multiplies objective and regularizer values by their declared weight or strength. Returned scalars must be finite, on the execution device and use the prediction/signal dtype.

## Optimizers

```python
def register_optimizer(
    name, factory, *, validate=None, package=None, package_version=None
): ...
```

Factory: `factory(parameter_groups, config) -> torch.optim.Optimizer`. Use `lang.CustomOptimizer(definition, **config)`. The executor supplies selected parameter groups and their learning rates, then calls standard `zero_grad`, `step` and constraint enforcement.

Checkpointing supports per-parameter tensor state and JSON scalar state, including stateless optimizers. Load the same recipe and make its referenced implementation modules available before resuming; registration is restored automatically. Scheduler state, arbitrary Python objects and custom global optimizer state are not automatically captured. External training loops can manage these separately.

## Surrogate gradients

```python
def register_surrogate(
    name, derivative, *, validate=None, package=None, package_version=None
): ...
```

Callback: `derivative(value, config) -> Tensor`, with the same shape/device/dtype as `value`. Use `lang.CustomSurrogate(definition, **config)`. The executor keeps a hard threshold in the forward pass and multiplies the backward gradient by this derivative. This applies to built-in spiking neurons and custom neurons using `context.spike`; a custom neuron that thresholds independently owns its own backward behaviour.

For direct PyTorch construction, pass the serialized custom specification as `GraphExecutor(..., surrogate=recipe["surrogate"])`.

## Dataset encoders and inputs

```python
def register_encoder(
    name, function, *, validate=None, package=None, package_version=None
): ...
```

Callback: `function(arrays, selected, *, dt_ms, channels, config, seed) -> Tensor`. Return binary `(time, selected_samples, channels)` spikes. Use `DatasetEncoder(kind="custom", definition="my_lab.encoder/v1", config={...}, seed=...)` inside `DatasetSnapshotBinding`. The resolved protocol retains the definition, configuration, seed and snapshot identity. Dataset snapshot labels remain integer labels.

Encoders can opt into device preparation by adding an explicit optional keyword, `device="cpu"`, to that signature. The resolver passes the execution device; generate tensors and local seeded `torch.Generator(device=device)` draws there when supported. Legacy callbacks receive their original arguments. Accelerator preparation records `snnlab.encoder-device/v1`, backend and PyTorch version in encoder provenance; CPU identities remain unchanged. use a new versioned definition if the random stream changes. Encoders still run on the caller thread, including prefetched lookahead, so scoped global RNG restoration cannot race training. CPU encoder outputs use bounded pinned/asynchronous transfer queues on CUDA.

Dataset encoders belong to external execution bindings, so the network bundle does not carry their definitions. Register the encoder's import reference when constructing that binding in each process.

For arbitrary generators, temporal patterns or preprocessing, a normal Python function can instead produce a tensor supplied through [DenseArrayBinding](/api/sim/execution-spec#densearraybinding). This also supports non-spike continuous inputs. No new generator interface is necessary.

## Diagnostics and saved state

Official outputs, exposed diagnostics and `.numpy()` work for registered signal ports. Custom dynamic state and current traces use runtime-state artifact version 2; existing conductance-only state artifacts remain version 1 and are still readable. Continuation detaches previous state, so it does not perform backpropagation across saved trajectory boundaries.

The graph executor keeps `runtime_state.currents` separate from `.conductances`; registered hidden neuron/synapse state lives in `.custom_state`. Registered callbacks must not keep mutable trajectory state outside their supplied state mapping if they need reproducible continuation. GPU support depends on using device-compatible PyTorch operations in your implementation.

## Runtime validation policy

Custom neuron/synapse steps and surrogate derivatives use structural validation by default. Opt into `extension_validation="strict"` while developing custom callbacks or investigating numerical failures. `simulate(..., extension_validation="structural")` or the same keyword on `GraphExecutor` keeps tensor contracts but skips per-step finite and binary-spike checks and backward derivative finite checks. Test callback numerical behaviour with strict mode before relying on structural mode. Invalid values may propagate silently. Initialization and restored state remain strictly checked. See [Execution Options](/api/sim/execution-spec) for the exact scope and CLI option.

## Registry and definition records

Import the registry functions and context records from `snnlab.extensions`. Specialized registrations return the same immutable `Definition` type as `register`.

```python
class Definition:
    name: str
    function: Callable[..., Any]
    initialize: Callable[..., Any] | None = None
    validate: Callable[[Mapping[str, Any]], None] | None = None
    unit: str = "1"
    state_units: Mapping[str, str] = field(default_factory=dict)
    classification: bool = False
    references: Mapping[str, str] = field(default_factory=dict)
    package: str | None = None
    package_version: str | None = None
    capture_safe: bool = False


def register(
    category: str,
    name: str,
    function: Callable[..., Any] | str,
    *,
    initialize=None,
    validate=None,
    unit="1",
    state_units=None,
    classification=False,
    package=None,
    package_version=None,
) -> Definition: ...


def get(category: str, name: str) -> Definition: ...


def resolve(category: str, spec: Mapping[str, Any]) -> Definition: ...


def definitions(category: str | None = None) -> tuple[Definition, ...]: ...
```

`register` accepts categories `neuron`, `synapse`, `initializer`, `constraint`, `operation`, `objective`, `regularizer`, `optimizer`, `surrogate` and `encoder`. Prefer specialized registrations for their unit-aware argument names. Invalid category/name/callback/unit metadata, missing packages and duplicate registrations fail. A registration modifies the process-local registry.

`get(category, name)` returns an existing definition or raises `ValueError`. `resolve(category, spec)` also runs its configuration validator, using `spec["definition"]` and `spec.get("config", {})`. `definitions(category=None)` returns a sorted tuple of records, optionally filtered by a validated category. These inspection calls do not execute neuron/synapse steps.

`Definition.function`, `.initialize` and `.validate` retain resolved callbacks; `references` records portable import references. `unit`, `state_units` and `classification` define runtime contracts; package fields record dependency provenance. Returned state-unit/reference mappings are read-only for registered definitions.

## Dependency metadata helpers

```python
def required(graph, training=None): ...


def restore(data): ...
```

`required(graph, training=None)` returns descriptors for used custom definitions, combining saved metadata and registered definitions; conflicting saved descriptors fail. `restore(data)` loads descriptor callbacks, validates exact declared dependency versions and populates the registry. Existing conflicting registrations fail. Normal bundle loading calls restoration after integrity checks; applications ordinarily do not call these helpers directly. Import references identify functions, not immutable source-code digests.

Native custom objectives and regularizers validate results against the prediction/signal tensor’s resolved device, including indexed MPS/CUDA devices. Returning a tensor on another device still raises a contract error.

### CUDA capture safety

All registration functions accept `capture_safe=False`. Set it to `True` only for deterministic tensor callbacks whose function and initializer avoid host tensor reads, random draws, Python side effects and external state. During CUDA replay Python runs during warmup/capture; only recorded CUDA work repeats. Unmarked callbacks use normal execution. Tensor contracts remain checked, and finite checks for captured objectives/operations are evaluated after replay with named errors. Strict dynamics validation keeps normal execution. See [automatic execution controls](/api/sim/execution-spec#gpu-performance-controls) for precision and replay policies.
