The supported reference covers authoring (`snnlab.lang`), graph execution (`snnlab.sim`), visualization (`snnlab.viz`), NumPy analysis (`snnlab.analysis`) and shared Python extensions (`snnlab.extensions`).

```python
from snnlab import lang, sim, viz, analysis, extensions
from snnlab.sim import ExecutionSpec, simulate
```

Each package's `__init__.py` is its central public export location. All supported functions and types are accessible through `import snnlab as snn` and `snn.lang`, `snn.sim`, `snn.viz` or `snn.analysis`, without submodule imports. All four packages resolve exports lazily, and subpackages are imported on demand. The former `snnlab.sim.execution` import path has been retired; import its supported functions and types from `snnlab.sim`. `snnlab.__version__`, `lang.__version__`, `sim.__version__` and `viz.__version__` are version strings.

## Finding an API

1. [Lang](/api/lang/network) creates declarations; [Compilation](/api/lang/compilation) validates and writes architecture bundles.
2. [Execution Functions](/api/sim/execution-functions) runs [ExecutionSpec](/api/sim/execution-spec) requests and returns [ExecutionResult](/api/sim/execution-result).
3. [Training Checkpoints](/api/sim/training-checkpoints) stores weights/optimizer progress; [Runtime State](/api/sim/runtime-state) stores ongoing dynamics.
4. [Viz](/api/viz/plotting) composes figures and animations; [Analysis](/api/analysis) measures recorded arrays.
5. [Extensions](/api/lang/extensions) registers versioned callback implementations shared by authoring and execution.

Reference signatures use Python typing names (`Any`, `Mapping`, `Sequence`, `Callable`, `Literal`), dataclass factories (`field`) and module aliases (`torch`, `np`, `nn`) as annotations/default notation. Import the symbols you call; signature blocks describe contracts and are not standalone scripts. Constructor validation may be followed by graph-dependent compilation/execution validation.

## Migrating replay and reference code

Replace private implementation imports with the supported package exports below. Existing function signatures, physical units, source-data ordering and seeded CPU arithmetic are retained.

| Former implementation import | Supported import |
| --- | --- |
| `snnlab._shared.timing` | `from snnlab.lang import duration_steps, duration_metadata, refractory_metadata` |
| `snnlab.sim.inputs.datasets` | `from snnlab.sim import load_dataset` |
| `snnlab.sim.inputs.encoders` | `from snnlab.sim import encode_images_poisson` |
| `snnlab.sim.graph.dynamics` (explicit drive) | `from snnlab.sim import poisson_spikes` |
| `snnlab.sim.graph.dynamics` (reference checks) | `from snnlab.sim import fast_sigmoid_spike, lif_step_expeuler, init_lif_state` |

For freshly authored historical COBA LIF replay graphs, use `lang.compile(net, refractory_timing="legacy_coba")`. Declare refractory durations as ms quantities and set `allow_autapses=True` on connections that require historical self-feedback. Compilation authenticates the graph, manifest and optional training recipe together; consumer-side marker or digest patching is unnecessary. See [historical replay](/api/lang/compilation#historical-coba-replay), [source arrays and seeded encoding](/api/sim/execution-functions#explicit-source-data), and [reference kernels](/api/sim/execution-functions#numerical-reference-helpers).

The default remains `"following_steps"`. Reauthoring changes graph identity; retained bundles and checkpoints stay paired with their original authenticated graph. [Runtime compatibility](/api/sim/runtime-state#compatibility-and-signatures) distinguishes explicit legacy scheduling. CUDA generator draws use CUDA's RNG; they need not match CPU draws.

## Source organisation

### Lang

`lang/__init__.py` is the central public authoring export map. The files below are internal; importing the package or building networks does not load simulator implementations or PyTorch. `snnlab.extensions` remains the shared public registry.

| Implementation | Responsibility | Reference |
| --- | --- | --- |
| `network.py` | Network declarations, population/projection/parameter references and signals. | [Network](/api/lang/network) |
| `components.py` | Neuron and synapse specification constructors. | [Components](/api/lang/components) |
| `parameters.py`, `units.py` | Initializers, constraints, physical quantities and unit constants. | [Parameters and Constraints](/api/lang/parameters) |
| `operations.py`, `readouts.py` | Graph transformations, reductions and convenience readouts. | [Operations and Readouts](/api/lang/operations-readouts) |
| `training.py` | Data-only recipe, objective, regularizer, optimizer and surrogate declarations. | [Training](/api/lang/training) |
| `compilation/` | Compilation, separate graph/training validation, diagnostics, capabilities, canonical serialization, bundles and reports. | [Compilation and Bundles](/api/lang/compilation) |
| `diagrams.py` | Renderer-neutral structural diagram projection. | [Structural diagrams](/api/lang/compilation#structural-diagrams) |

`_specs.py` contains private specification primitives. Private serialization helpers stay outside the public export list. Legacy operations namespace access is retained for hash-pinned recipes; current application code uses the direct package exports above.

### Sim

`snnlab.sim` is the only public simulation export location. Its central export map resolves the internal packages below lazily; applications should use the package imports listed above. The internal package initializers do not re-export the API.

| Internal package | Responsibility | Reference |
| --- | --- | --- |
| `requests/` | Request specifications, result types and execution handlers. | [ExecutionSpec](/api/sim/execution-spec), [ExecutionResult](/api/sim/execution-result), [Execution Functions](/api/sim/execution-functions) |
| `inputs/` | Binding declarations, file resolution, datasets, encoders and batch providers. | [Input bindings](/api/sim/execution-spec#input_bindings), [resolution helpers](/api/sim/execution-spec#input-resolution-helpers) |
| `graph/` | Planning, PyTorch graph execution, numerical dynamics, kernels and extension helpers. | [GraphExecutor](/api/sim/graph-executor), [PyTorch Integration](/api/sim/pytorch) |
| `runtime/` | Trajectory state, recording, measurement, interventions, resets and decisions. | [Runtime State](/api/sim/runtime-state), [Recording and Measurement](/api/sim/recording-measurement), [Interventions](/api/sim/interventions), [Resets and Decisions](/api/sim/resets-decisions) |
| `training/` | Native trainer, batching/measurement policies, epoch observations, selection and checkpoints. | [Training controls](/api/sim/execution-spec#training-controls), [Training Checkpoints](/api/sim/training-checkpoints) |
| `artifacts/` | Bundle loading, authenticated inference products and shared integrity checks. | [Compilation](/api/lang/compilation), [Inference Artifacts](/api/sim/inference-artifacts) |
| `diagnostics/` | Bounded training tracing and internal numerical conformance tools. | [Tracing](/api/sim/tracing) |

Shared contracts live above the authoring and simulation packages in private `snnlab/_shared`: `neurons.py` owns built-in neuron validation and state units, `connectivity.py` owns structural connection rules, and `timing.py` owns physical-duration/timestep conversion. These modules depend only on the standard library and each other. Both `lang` and `sim` consume them; the shared layer does not import either package. `snnlab.extensions` remains the public callback registry, separate from simulation implementation helpers.

`cli.py` owns command-line parsing and request adaptation; `__main__.py` launches it for `python -m snnlab.sim`. Numerical implementations and request/result declarations do not import execution handlers or the trainer. Persisted format identifiers remain beside their formats.

### Viz

`viz/__init__.py` is the central public visualization export map. Every supported type and helper is available through `import snnlab as snn; snn.viz`, or `from snnlab import viz`. The implementation packages below follow the [Diagrams](/api/viz/diagrams) and [Plotting and Animation](/api/viz/plotting) reference sections; their initializers do not re-export the API.

| Implementation | Responsibility | Reference |
| --- | --- | --- |
| `recording.py` | Renderer-neutral time-series data and validation. | [Recording](/api/viz/plotting#execution-arrays-and-recording) |
| `transforms.py` | NumPy activity traces, projection activity and representative-frame selection. | [Transforms](/api/viz/plotting#numerical-transforms) |
| `diagrams/model.py` | Structural diagram nodes, edges, groups and theme. | [Diagram contracts](/api/viz/diagrams#diagram-data) |
| `diagrams/dot.py` | Deterministic DOT formatting. | [Diagrams](/api/viz/diagrams) |
| `diagrams/render.py` | Graphviz execution and SVG, PNG, PDF or DOT file export. | [Diagrams](/api/viz/diagrams) |
| `plotting/geometry.py` | Figure rectangles, named regions and point layouts without Matplotlib. | [Plotting and Animation](/api/viz/plotting) |
| `plotting/grid.py`, `plotting/scene.py` | FigureGrid rendering and panel composition around Matplotlib. | [Plotting and Animation](/api/viz/plotting) |
| `plotting/theme.py`, `plotting/animation.py` | Figure style, timeline sampling and video encoding. | [Plotting and Animation](/api/viz/plotting) |

Imports are lazy: diagram contracts and DOT formatting use only the standard library; recordings, transforms and geometry use NumPy without loading Matplotlib. Figure rendering, scenes and animation helpers load Matplotlib when accessed. Graphviz is invoked only for rendered diagram exports, not for DOT generation. Visualization does not import simulator implementations or PyTorch.

The former flat implementation modules are retired. Replace imports such as `from snnlab.viz.figure_grid import FigureGrid` with `from snnlab.viz import FigureGrid`; internal paths are not supported application imports.

### Analysis

`analysis/__init__.py` is the central lazy public export map for all 24 measurements. Use `import snnlab as snn; snn.analysis` or import functions directly from `snnlab.analysis`. Implementation modules are private and follow the groups in the [Analysis reference](/api/analysis).

| Implementation | Responsibility | Reference |
| --- | --- | --- |
| `activity.py` | Population/per-neuron rates, binned counts, rate traces, active fractions and population-count CV. | [Activity](/api/analysis#activity) |
| `intervals.py` | Within-presentation per-neuron intervals and ISI CV. | [Intervals](/api/analysis#intervals) |
| `correlations.py` | Correlations between binned neuron counts. | [Correlations](/api/analysis#correlations) |
| `spectra.py` | Spectra, spectral peaks, band power and fractions. | [Spectra](/api/analysis#spectra) |
| `rhythmicity.py` | Pooled events, interval histograms, autocorrelograms and rhythm descriptors. | [Rhythmicity](/api/analysis#rhythmicity) |
| `cycles.py` | Burst detection, cycle boundaries, counts and occupancy. | [Cycles](/api/analysis#cycles) |
| `conductance.py` | Conductance-loop scores and rolling summaries. | [Conductance](/api/analysis#conductance) |

Private `_validation.py` and `_sampling.py` own shared array validation, windowing, binning and smoothing. They remain local to Analysis. Package import alone loads neither NumPy nor SciPy. Basic measurements use NumPy; smoothing loads SciPy when requested, and spectra/cycle helpers load it on access. Analysis imports no simulator implementations, PyTorch or Matplotlib. Public signatures, numerical defaults and return conventions remain unchanged.
