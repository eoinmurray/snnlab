Changes to the combined snnlab Python distribution are recorded here. Package
versions use MAJOR.MINOR.PATCH. Component and serialized-schema versions identify
separate compatibility contracts.

## [Unreleased]

## [0.25.0] - 2026-10-23

### Added

1. `sim.prepare_stream` and `sim.StreamSession` for fixed-window inference with private frozen weights/state, warmed execution, cached metadata/masked weights, independently retained outputs, reset and portable state export. The API reference includes a complete runnable 1 ms window example, input/output contracts, session methods, trained-weight snapshots and application-owned scheduling.
2. `benchmarks/streaming/benchmark.py` measures scalable random networks using 0.1 ms numerical steps and 1 ms model windows. One script generates callback and internal `stream.advance` timing bar charts, saves raw measurements and redraws saved reports with `--plot-only`. Measurements are warmed and unpaced; deadline scheduling, latency plots, operator/cProfile captures and separate helper scripts have been removed. Renamed from the development `benchmarks/realtime` harness.

### Changed

1. Compiled CPU/CUDA tensor kernels and network blocks now select native C++ wrapper dispatch, preserving precision-cast emulation and the existing PyTorch 2.10 reduced-precision CPU fallback. MPS keeps compiled Metal kernels with Python dispatch after native code generation failed on missing `get_mps_lib_*_handle` symbols. Execution/stream metadata records wrapper selection and fallback reasons.
2. Compiled network blocks batch dense external input projections across each block and defer terminal populations to batch eligible readout projections. Recurrent dependencies, delays, per-step gains and numerical timesteps are preserved; pooled/convolutional projections remain per-step. The shared block path supports streaming, simulation and training, with forward, gradient and continuation checks.

## [0.24.1] - 2026-10-23

### Added

1. Runnable Hodgkin–Huxley neuron extension with sodium, potassium and leak currents, gating dynamics, an independent SciPy trajectory comparison and focused regression tests. The example, figures and comparison data are included in the documentation and source distribution.

### Changed

1. Consolidated API Reference into five curated module pages: `snnlab.lang`, `snnlab.sim`, `snnlab.extensions`, `snnlab.analysis` and `snnlab.viz`. Former API page URLs redirect to the consolidated references, including deployments beneath `/snnlab`.
2. Simplified documentation navigation: API Reference precedes Benchmarks, library comparisons and Changelog; PyTorch Integration appears immediately before Animate a Simulation. Removed the Model Components and Results and Analysis guide groups and their six pages, updated remaining links and removed the retired Neurons publishing pipeline.
3. Bundle graph, training and manifest JSON files now use sorted, indented UTF-8 text with a trailing newline. Canonical digest calculation and bundle verification remain unchanged.

## [0.24.0] - 2026-10-23

### Added

1. Continuous population voltage and declared neuron-state sources for custom synapses with explicit `input_unit`. Dimensionless weights act before nonlinear gating; continuous sources sample beginning-of-step state, with explicit whole-step delays and persistent source/gate histories. Reciprocal graph connections update gates before membrane integration without an implicit recurrent delay. Includes a CPU float64 graded-inhibition example and independent Euler, batching, saved continuation and unit-validation tests. Existing spike projections and legacy extension descriptors retain their contracts.

## [0.23.0] - 2026-10-20

### Added

1. Public `sim.TrainingHistory` reads native metrics from memory or saved evidence, exposes immutable epoch/split, selection, held-out test and performance records, and extracts curves without filling missing observations. Explicit validation covers completion expectations, metric domains, counts/encoding draws and available checkpoint-selection/test provenance, preserving online training, fixed-weight baselines and partial/resumed histories.
2. Public `sim.NetworkSnapshot` provides metadata-only structured access to native snapshots, physical parameters/units, projection shapes, initializer/scaling/constraint definitions and resolved trainable/frozen membership. Explicit parameter loading verifies integrity and returns independent CPU tensors with original dtypes; initialization statistics remain distinct from final-weight measurements.
3. `ExecutionResult.numpy(batch=...)` now includes retained recorded signals through `recorded_signals` and `recording: sim.RecordingData`, with declared axes, original cell/sample identities and per-signal time coordinates. Numeric NumPy conversion explicitly expands bfloat16 to float32; original tensors and their computation graphs remain intact.
4. Explicit `result.write_metrics` and `result.write_recording` exporters, paired with `sim.read_metrics` and `sim.RecordingData.read`, publish versioned native evidence with opt-in overwrite. Metrics use `snnlab.metrics/v1`; recordings extend the existing NPZ-block format with axes and coordinates while preserving exact bfloat16 storage. Export never performs execution, selection, analysis or RNG draws.
5. Public `sim.DatasetPartition`, `sim.DatasetSnapshot` and explicit `sim.stratified_split(..., policy="stratified-v1")` support portable named feature/label partitions, original sample IDs, disjointness/integrity checks and existing native encoder bindings. Archive schema `snnlab.dataset-snapshot/v1` retains rows, shapes, dtypes and caller-declared preprocessing/provenance; diagnostic members retain their original split identity.
6. `viz.plot_raster` and `viz.plot_learning_curves` draw saved evidence on caller-owned axes and return artists. Raster coordinates preserve selected cells and actual recording times; learning curves retain gaps and measurement semantics, with held-out test markers separate from curves. Optional `sim.format_epoch` and `sim.EpochLogger` format finalized epoch reports without extra evaluation.
7. Public `build`, `simulate` and `train` accept authored `lang.Bundle` objects alongside saved paths, validating copied graph/recipe data and asset integrity without temporary write/read cycles. Existing explicit graph/training precedence and path execution identities remain supported. Added an offline digits example demonstrating explicit calls, local snapshot configuration, readers, exporters and plotting.

### Removed

1. Removed `snnlab.sim.infer` and its internal request kind. Use `snnlab.sim.simulate` with the same keyword arguments for inference, including checkpoint loading, runtime continuation, recording and performance policies. New inference run snapshots now record `kind="simulate"`. The execution benchmark uses `--mode simulate` for forward-only runs; retained historical reports may still record `infer`.

## [0.22.0] - 2026-10-20

### Added

1. Public immutable, keyword-only `snnlab.sim.Performance` shared by `build`, `train`, `infer` and `simulate`. Defaults are `compile_mode="default"`, `compile_block_steps="auto"`, `cuda_graphs="auto"`, `precision="auto"`, `fused_optimizer="auto"`, `dataset_prefetch=1` and `projection_mode="fast"`. Omission or `performance=None` uses these defaults. `result.metrics["performance"]` consolidates requested settings, resolved policies, observed paths and fallback reasons; build-only results distinguish preparation from execution. Device, workload, validation, recording and timing controls remain on the operation.
2. Durable Modal comparisons of the full digits, MNIST/snnTorch and SHD workloads retain per-policy logs, metrics, actual GPU identities and source hashes. The digits benchmark now accepts `--device cuda:0` and has a paired L4 launcher; its default stays eager CPU. Public training calls in all three recipes use `Performance` without changing their workload or evaluation schedule.
3. Added a Performance and Custom Components guide with per-setting compatibility, CUDA capture contracts, mixed-precision state handling, validation and cold/warm measurement guidance. The customisation example now uses validated, capture-safe custom adaptive neurons and exponential current synapses with shared weights, whole-tensor updates, scalar reset broadcasting and stable recurrent dtype. CPU/CUDA device selection, eager/strict debugging and saved performance metrics make its actual paths inspectable; the one-pass plotting example does not claim a replay speedup.

### Changed

1. Enable supported accelerator speed paths automatically: CUDA 16-step blocks, MPS 4-step blocks, one-batch prefetch, CUDA BF16 autocast/TF32, fused native Adam/AdamW and bounded forward-only replay. Explicit opt-outs remain available and metrics report selected paths/fallbacks. Precision can change spike decisions and learning outcomes. Custom tensor callbacks declare `capture_safe=True` before replay; validation host reads occur after capture with named errors. Training replay supports approved custom callbacks and AMP, while optimization, reporting and persistence remain in the native loop.
2. Individual performance keywords on public execution functions remain compatible but emit `DeprecationWarning`; move them into `performance=Performance(...)`. Mixing a non-`None` object with any old performance keyword raises `TypeError`, including explicit default values. Normalization preserves existing execution/checkpoint identities. Internal requests, CLI flags and direct `GraphExecutor` constructor controls are unchanged.
3. Ordinary inference automatically scopes `no_grad` when inputs/parameters need no gradients and registered callbacks are capture-safe. Differentiable inputs, trainable parameters and runtime continuation retain the existing autograd behavior. Forward replay caches at most two repeated shapes after warmup, returns independent result tensors and reuses shapes across dataset offsets while correcting per-batch metadata.
4. Renamed the automatic device-selection environment variable from `PINGLAB_DEVICE` to `SNNLAB_DEVICE`. Update shell exports and deployment configuration; the old name is no longer read. Explicit API/CLI device choices still take precedence, and automatic selection still uses CUDA when available, otherwise CPU, with MPS available explicitly.

### Fixed

1. Correct the MNIST comparison's native wall timer and explicitly retain its initial and per-epoch fixed-weight train/test evaluations.
2. Preserve model dtype for zero-decay synaptic state under automatic mixed precision, including runtime continuation.
3. Compiled kernels preserve intermediate dtype casts, correcting recurrent bfloat16 gradient differences above 30% under compiler fusion. Results record `snnlab.eager-precision-casts/v1`. Added actual Inductor output/gradient/Adam regressions on CPU, CUDA and MPS, including a value-preserving workaround for Metal's bfloat16 absolute-value overload and an explicit eager tensor-graph fallback for reduced-precision CPU execution on PyTorch 2.10.
4. CUDA precision support checks and stream waits use the model/stream's actual device. Replay value validation defers host reads until after capture, preserving named finite-value errors. Existing portable callback descriptors without a capture annotation remain loadable; installed registration determines eligibility, and only affirmative capture annotations are serialized.

### Performance measurements

1. Matched full-workload native calls on Modal measured MNIST L4 at 166.23 s / 42.30 s before/automatic (3.93×), with accuracy 80.01% / 85.64%; fresh snnTorch took 169.09 s at 85.20%. SHD H100 measured 1107.88 s / 518.63 s (2.14×), with accuracy 47.30% / 46.32%. MNIST replayed all 940 updates and SHD all 290, each with two captures and no replay fallbacks. These are single-seed measurements; precision changes learning trajectories.
2. Digits eager CPU measured 4.30 s / 3.90 s at 93.61% in both conditions; treat the small difference as timing variation. A separate L4 pair measured 30.24 s / 80.51 s including startup, at 93.33% / 94.17%. Warm epoch medians improved from 312.37 ms to 22.56 ms (13.85×), but compilation/capture dominated the full automatic GPU run. All 240 automatic updates replayed with two captures and no replay fallbacks. Warm epochs are not a separate full-call rerun. Conditions ran serially with potentially shared compiler caches. See `benchmarks/execution/results/automatic-defaults/README.md` and its linked raw reports for timing scopes, memory, provenance and limitations.

## [0.21.0] - 2026-10-19

### Changed

1. Public `build`, `simulate`, `infer` and `train` now accept explicit keyword-only arguments with operation-specific signatures. Remove `ExecutionSpec(...)`, `kind` and `executor` from Python calls; pass `inference_overrides=` directly instead of `options["inference_overrides"]`. `ExecutionSpec` and `execute_request` are internal and no longer exported from `snnlab.sim`. The CLI and execution semantics are unchanged.
2. Runtime `torch.compile` is now the default in `ExecutionSpec`, `GraphExecutor` and the CLI. Prepared kernels cover built-in/custom neuron and synapse updates, custom graph operations, surrogate derivatives and post-update weight constraints. Custom callback signatures are unchanged; definition/configuration lookup is moved out of timestep loops. Strict custom-surrogate checks retain an eager autograd boundary. Initialization and training orchestration stay eager. Select Python `compile_mode=None` or CLI `--compile-mode eager` for unsupported environments or debugging; compilation errors surface explicitly.
3. Added PyTorch callback performance guidance to customisation, neurons, synapses, weights and the extension/API references, including vectorization, stable tensor state, avoiding host reads, compiler warmup and eager/compiled numerical comparisons.

### Added

1. Opt-in bounded network compilation through `compile_block_steps=2..64` and `--compile-block-steps`, reusing reference projection/synapse/neuron equations with ordered delays, spatial routing and modulation. Metrics expose selected paths and conservative compatibility fallbacks; blocks preserve internal gradient history and partial blocks. Added matched end-to-end benchmark tooling with numerical gates, cold/warm samples, profiler counts and provenance. MPS currently limits the opt-in path to four-step blocks after larger graphs exceeded compiler buffer bindings. Added Modal H100 validation and standalone fixed-shape CUDA Graph training replay experiments; public replay modes remain disabled.
2. Device-local Poisson input/dataset generation from compact rates/features, with an explicit accelerator RNG policy and preserved CPU stream; indexed/vectorized event datasets; optional device-aware encoder callbacks and caller-thread custom prefetch preparation. Checkpoints bind the recorded encoding backend/policy.

### Fixed

1. Floating runtime state and built-in spike functions follow model dtype, fixing recurrent `.half()` matrix-multiplication failures. Added CPU/CUDA/MPS dtype, gradient, state and continuation regressions; MPS float64 remains unsupported. Bfloat16 runtime/checkpoint/NPZ recording tensors use lossless versioned bit storage; inference analysis caches record an explicit lossless float32 expansion. Portable MPS measurement states stage restored accumulators before stepping, and native custom losses validate the resolved tensor device.
2. Replay windows/routing are staged before stepping, CUDA recording chunks transfer asynchronously to bounded pinned host buffers, decision counts transfer together after stepping, and strict state/constraint finite flags consolidate host reads without weakening validation. Unconstrained parameters avoid post-update copies. The SHD custom encoder now supports compact device binning/noise while preserving CPU NumPy draws and CPU protocol identity.

## [0.20.1] - 2026-10-19

### Fixed

1. Restored epoch-zero validation by default with `TrainingMetrics.initial=("validation",)`. Validation still runs after every completed epoch, and held-out test evaluation still runs only after training finishes. Use `initial=()` to skip the initial validation pass.

## [0.20.0] - 2026-10-19

### Changed

1. Epoch training now defaults to validation after every completed epoch, selection by lowest total validation loss, and one final test evaluation when `ExecutionSpec.test=TestSpec(...)` is supplied. Test evaluation uses the selected checkpoint or final weights, never informs selection, and waits until all requested epochs complete across resume. Results appear in `metrics["test"]` without changing the final model/optimizer/checkpoint. `TrainingMetrics.initial` now defaults to `()`; `test="none"` disables testing. Added total-loss checkpoint selection for classification and regression recipes.

## [0.19.2] - 2026-10-19

### Changed

1. `TrainingMetrics()` now defaults to online training metrics, epoch validation, initial validation only and no per-update history: `train="online", validation="epoch", initial=("validation",), update_history=False`. Omitting the policy uses these defaults. Online epoch reporting retains completed history and partial sums in resumable checkpoints. Implicit update-loss checkpoint selection is disabled with update history; request an explicit selection policy when needed.
2. To retain the previous measurement behavior, pass `TrainingMetrics(train="evaluate", validation="epoch", initial=("train", "validation"), update_history=True)` for epoch training. Updated metric documentation and focused policy, observation and checkpoint regressions.

## [0.19.0] - 2026-10-16

### Added

1. Spatial geometry through optional `spatial_shape=(channels, height, width)` on inputs and populations, with inferred population size and flat channel-major execution tensors. `Network.connect(connectivity=lang.Conv2d(...))` supports compact shared kernels, integer/pair kernel sizes, stride and zero padding independently of current/conductance synapse dynamics. Geometry and kernel shape are validated before execution; existing dense graphs retain their defaults and serialized data.
2. `lang.pool2d` adds average and max spatial pooling, including pooling chains feeding dense/convolutional projections with causal delays. Average pooling excludes padding and produces continuous fractional drive; max pooling preserves the input signal type. Same-population convolution requires explicit `allow_autapses=True`; count-valued event encoding remains deferred.
3. Convolution/pooling support gradients, compact shared parameters, native training, bundle/checkpoint serialization, run snapshots, recording and runtime continuation. Added PyTorch arithmetic/gradient comparisons and integration coverage plus conceptual/API documentation. No new runnable example is included.

### Changed

1. All network diagram views now show populations, operations and projections explicitly, with groups rendered as labelled boundaries. `"expanded"` remains an alias for the explicit circuit view; the `expand_groups` argument has been removed from `lang.diagram` and `Bundle.visualise`. The static complexity limit applies to all views.
2. Diagram rendering now uses semantic node colours, aligned forward paths, separated feedback lanes and positioned training annotations. Added retained-graph regression/visual fixtures, refreshed existing example diagrams and updated the PyTorch integration diagram to show the spiking network's internal structure.

## [0.15.0] - 2026-10-15

### Added

1. Optional `snnlab.sim.TraceSpec` on native training requests supports `off`, `monitor`, `profile` and `both` modes over bounded update windows. Monitoring reports detached input/population activity, numerical weight/gradient sparsity, block sparsity, phase enqueue/current-stream timings, boundary CUDA memory and process CPU/RSS measurements. PyTorch Profiler adds operator/allocation tables and Chrome traces, with estimated FLOPs, kernel interval coverage and copy bandwidth where Kineto exports bytes. Hardware counters outside the backend remain explicitly unavailable; tracing is excluded from checkpoint identity.
2. Added `benchmarks/shd` with the calibrated feedforward COBA Lang recipe, batch 256, ten epochs and native `snnlab.sim.train()`, verified SHD acquisition/splitting, final checkpoints, timings and a Modal H100 launcher. CLI tracing controls run a separate bounded diagnostic after baseline training; profiler overhead is excluded from baseline reports. Tracing documentation defines metric scopes, overlap, instrumentation overhead and unsupported counters.

3. Added a run-pinned SHD workload report with learning, baseline epoch timing, sparsity and diagnostic timeline figures, protocol/results/operator/observability tables and downloadable retained data. A streaming trace extractor distinguishes actual CUDA kernels from annotation spans; publication checks source, figure and recipe hashes. Baseline measurements remain separate from the instrumented early-training capture.

### Changed

1. SHD's Python Modal launcher now submits a single durable `.spawn()` call inside `app.run(detach=True)` and immediately saves its run/call IDs. The cloud worker writes its own completion manifest and commits artifacts independently of the client. A separate volume-only collection command downloads reports later without starting GPU work; the explicit Modal CLI path is documented with `--detach`.

2. Simulation functions and types now use the central lazy `snnlab.sim` export map. Internal implementations are grouped into `requests`, `inputs`, `graph`, `runtime`, `training`, `artifacts` and `diagnostics`, matching the API reference responsibilities. Binding declarations live in `inputs/bindings.py`; format identifiers and shared helpers live with their owning domains. Package initializers do not add secondary export surfaces. CLI adaptation is consolidated in `cli.py`, and the unused legacy stopwatch module is removed. Public export names, numerical defaults and persisted format identifiers are unchanged. Removed the former `snnlab.sim.execution` compatibility module and flat implementation paths; migrate imports such as `from snnlab.sim.execution import ExecutionSpec, simulate` to `from snnlab.sim import ExecutionSpec, simulate`.

3. Private neuron and connectivity contracts now live in `snnlab/_shared/neurons.py` and `snnlab/_shared/connectivity.py`; shared physical-time conversion moves from the simulator into `snnlab/_shared/timing.py`. The shared layer depends only on the standard library and itself, so authoring and the public `snnlab.extensions` registry no longer import simulator implementations for timing. The registry remains at its public location; simulation exports, timing semantics and persisted formats are unchanged.

4. Lang authoring now has a central lazy public export map: constructors, operations, readouts, recipe helpers and documented validation types are available directly from `snnlab.lang`. Package-root lazy access supports `import snnlab as snn; snn.lang.Network(...)`. Split the former `core.py` into network, component, parameter, unit and private specification modules, and split compilation into validation, diagnostics, capabilities, serialization, bundle and reporting modules. Current docs and examples use direct package exports; private helper imports follow their implementation owners. Legacy operations namespace access remains available for hash-pinned benchmark recipes without adding module namespaces to the advertised API. Public component defaults, bundle formats and canonical identities are preserved.

5. Viz now uses `viz/__init__.py` as its central lazy public export map, with every supported object accessible through `import snnlab as snn; snn.viz`. Internal `diagrams` and `plotting` packages follow the API reference: diagram models, DOT formatting and Graphviz export are separated, as are plotting geometry, grids, scenes, themes and animation. Renamed recording contracts to `recording.py`; numerical transforms remain in `transforms.py`. Geometry imports no longer load Matplotlib. Public export names, rendering defaults and numerical behaviour are preserved. The former flat implementation paths are retired; migrate submodule imports to `from snnlab.viz import ...`.

6. Analysis now resolves its 24 public functions lazily from `analysis/__init__.py`, all accessible through `import snnlab as snn; snn.analysis`. Internal files follow activity, intervals, correlations, spectra, rhythmicity, cycles and conductance reference groups; private validation and sampling helpers remove cross-domain helper ownership and the former activity/spike circular dependency. Basic measurements no longer load SciPy unnecessarily; smoothing loads it when needed. Retired private implementation paths in favour of direct `snnlab.analysis` imports. Public signatures, numerical behaviour, rounding, status values, metadata and historical return conventions are preserved. Updated the guide, reference, source map and API tests.

The CPU tracing/SHD acceptance suite passed 24 tests with one CUDA skip, covering exact unchanged weights, gradients, Adam/RNG state and resume, known sparsity counts, interval unions, empty/truncated windows, exception cleanup, portable bundles and separation of baseline/diagnostic calls. The broader local simulation suite passed 860 tests with 22 skips and two deselections. CUDA tracing has not been executed locally. Documentation type checks and root/base-path static builds passed.

## [0.13.0] - 2026-10-14

### Added

1. `training.FastSigmoid` now accepts independent `gradient_scale` and `threshold_inclusive` settings. Training bundles and direct executors preserve the complete configuration, allowing the SHD derivative with slope `100/15`, scale `1/100` and strict threshold comparison to use compiled built-in neuron kernels. Non-default scales use an exact hard forward with an explicit tensor-only backward, avoiding CUDA fusion residuals from a scaled detach proxy. Exclusive built-in thresholds bind runtime-state compatibility; resolved surrogate and compilation settings appear in execution metrics. Defaults retain historical forward/backward arithmetic and serialized recipe identity; registered derivatives still execute eagerly.
2. Added a synthetic SHD-shaped COBA/delayed-PING profiling harness and Modal H100 launcher under `benchmarks/shd-compilation/`. It separates cold updates, warmed forward/backward/update timings, allocated GPU memory and CPU/CUDA profiles across batches 32, 256 and 8. On one H100, batch-256 synthetic 1,000-step updates measured 2.718 → 1.716 s for registered-to-compiled COBA and 5.582 → 3.242 s for registered-to-compiled delayed PING, with higher cold costs. Raw samples, profiles and limits are retained alongside the harness. This prepares timestep fusion; no timestep-block path or general speedup is established.

3. Added opt-in `ExecutionSpec.training_timing` and CLI `--training-timing` for graph training. Results report disjoint setup, training, training-split evaluation, validation/probe, final checkpoint and reporting durations, plus per-epoch phase durations. Synchronized mode fences CUDA/MPS at phase boundaries; enqueue mode reports host latency. Disabled timing adds no timing clocks or fences. Timings cover only work performed in the current call and do not alter checkpoint, recipe or resume identity.

4. Added a dedicated MNIST snnTorch/SNNLab comparison page with matched architecture and training settings, run-pinned learning curves, the complete timing table, measurement definitions and downloadable figure/raw results. The report retains the independently trained accuracy gap and limits its speed claims to the measured workload.

### Changed

1. The MNIST snnTorch comparison now measures matched setup/training/initial-and-epoch-evaluation/in-memory-checkpoint scopes, with disk writes and Modal volume commits outside both timers. SNNLab uses one public `train()` call; isolated forward/backward profiling remains separate from training throughput. The benchmark retains three code files and three result files.

2. Preserved the retired zero-decay model helpers and reference data under test fixtures, retaining sustained training acceptance coverage after benchmark cleanup. The current MNIST harness accepts newer releases while requiring its projection/snapshot and training-timing APIs.

### Validation

1. The final focused local suite passed 115 tests (15 CUDA-dependent skips). The H100 regression suite passed 51 checks, including actual CUDA compilation, exact binary spikes, trajectories, gradients, Adam state and runtime continuation. Small spiking COBA/PING probes passed at `atol=rtol=2e-5`; full 1,000-step training-trajectory equivalence is not established.
