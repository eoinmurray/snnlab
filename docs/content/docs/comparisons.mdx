title: Comparison with Other SNN Libraries
description: How SNNLab's declarative network language and experimental workflow compare with snnTorch, Brian 2 and NEST.
---

SNN libraries serve different purposes. Some focus on learning from neuromorphic datasets; others focus on biological network dynamics. SNNLab brings explicit circuit modelling and surrogate-gradient training into one workflow, with **`snnlab.lang` as the shared description of the network**.

This guide compares design choices, rather than ranking libraries overall. It draws on the projects' official documentation, reviewed on 9 October 2026. It is not a performance benchmark: we have not established that SNNLab is faster, more accurate or more scalable than these alternatives.

For measured learning curves and execution timings on a matched current-based classifier, see the [MNIST snnTorch comparison](/snntorch-comparison). Its results apply to that specific model, dataset subset and hardware.

## At a glance

| Library | Main emphasis | How networks are described | Why consider SNNLab instead? |
| --- | --- | --- | --- |
| [snnTorch](https://snntorch.readthedocs.io/en/latest/) | Gradient-based SNN learning | Spiking neurons composed with ordinary PyTorch layers | Named populations, synapses, outputs and constraints in a separate authoring language. |
| [Brian 2](https://brian2.readthedocs.io/en/stable/user/models.html) | Flexible neuroscience modelling | Differential equations, neuron groups and synapses | Built-in differentiable execution of an authored circuit, with reusable bundles and training recipes. |
| [NEST](https://www.nest-simulator.org/) | Biological network dynamics and large simulations | Python commands creating model instances, connections and recording devices | A PyTorch training path using the same graph as simulation and inference. |

## What `snnlab.lang` brings to the workflow

`lang` lets you describe **what the circuit contains** before choosing the inputs and execution request. Populations, projection dynamics, weight initializers, constraints and observable signals have explicit names. You can inspect the compiled description without advancing the simulation.

Here is a complete authoring example: four input channels drive sixteen conductance-based LIF neurons through an excitatory AMPA projection.

```python
from snnlab import lang

net = lang.Network(
    "comparison",
    dt=0.1 * lang.ms,
)
inputs = net.input(
    "inputs",
    shape=("time", "batch", 4),
    signal_type="spikes",
    unit="spike",
)
cells = net.population(
    "E",
    size=16,
    neuron=lang.COBA_LIF(tau_mem=20 * lang.ms),
)
projection = net.connect(
    inputs,
    cells.excitatory,
    name="input_to_E",
    synapse=lang.AMPA(tau=2 * lang.ms),
    weight=lang.Uniform(
        0.1,
        0.5,
    ),
    constraint=lang.NonNegative(),
)
net.output(
    "spikes",
    cells.spikes,
)
net.expose(
    cells.voltage,
    name="e_voltage",
)
net.expose(
    projection.conductance,
    name="input_conductance",
)

bundle = lang.compile(
    net,
    target="tools/snnsim",
)
bundle_path = bundle.write("comparison.bundle")
```

![Diagram generated from the example's compiled graph: four input channels connect through one AMPA projection to sixteen conductance-based LIF neurons.](/comparisons/network.png)

This diagram is generated from the example's compiled graph. The boxes identify the input, neuron population and spike output; the AMPA-labelled connection identifies the synaptic projection. It describes the circuit structure, rather than measured activity or training performance.

The projection has 64 weights, sized automatically from the four source channels and sixteen target neurons. Its stored weights and conductance state use microsiemens. The default fan-in normalization divides the sampled weights by four at initialization; use `initialization_scaling="direct"` to retain their sampled magnitudes. AMPA here denotes simplified exponential conductance dynamics. The target port selects excitation.

The description makes several useful choices visible:

1. **The circuit is inspectable data.** Compilation produces `graph.json`, an optional `training.json`, a manifest and a report. Compilation validates and serializes declarations; it does not generate a standalone native simulation binary.
2. **Signals carry meaning.** Shapes, signal types and physical units support compatibility checks. Authoring, graph validation and execution planning check different parts of the contract; compilation alone does not guarantee that every declared feature can execute on a backend. Review `bundle.diagnostics` for capability reports and warnings before execution.
3. **Observations belong to the description.** Named outputs and optional diagnostics identify the spikes, voltages and conductances the experiment will expose.
4. **Diagrams follow the graph.** `lang.diagram(bundle)` produces a structural diagram from the compiled description. Rendering it with `viz.render_diagram` requires Graphviz. [Groups and reusable components](/api/extensions#built-in-neurons-and-synapses) help organise larger circuits.
5. **The architecture can travel between runs.** Save a bundle once, then supply different input bindings and execution settings. Optional [training recipes](/api/lang#trainspec) record parameter selection and training configuration alongside the graph.

Continue the example with a short simulation of the saved bundle:

```python
from snnlab.sim import PoissonInputBinding, simulate

stimulus = PoissonInputBinding(
    input_id="inputs",
    steps_count=1000,
    rates_hz=(80,),
    seed=17,
)
result = simulate(
    bundle=bundle_path,
    input_bindings=(stimulus,),
    seed=17,
    device="cpu",
)
data = result.numpy(batch=0)
print(data.outputs["spikes"].shape)  # (1000, 16)
print(data.diagnostics["e_voltage"].shape)  # (1000, 16)
```

This runs 100 ms at a 0.1 ms timestep. Changing the input stimulus does not require rebuilding the circuit. See [Quickstart](/quickstart) for a complete plotting workflow and [Compilation and bundles](/api/lang#compilation-and-bundles) for the persistence contract.

A bundle stores architecture, initializers and optional recipes; learned weights need a checkpoint, and continuing a running simulation needs its runtime state. File digests help detect changed bundle contents, but do not guarantee scientific reproducibility across environments. Custom extensions retain import references, so their external Python modules must be available when loading the bundle.

## snnTorch

[snnTorch](https://snntorch.readthedocs.io/en/latest/) treats spiking neurons as components that fit naturally into PyTorch networks. It provides surrogate gradients, encoders, plotting utilities, detailed learning tutorials and NIR import/export. Convolutional and residual architectures can use familiar PyTorch layers.

SNNLab also exposes a PyTorch `GraphExecutor`, but `lang` adds a separate description of the circuit. Instead of making a Python module's forward method the only expression of the architecture, you declare populations, projections, constraints and outputs that can be validated, saved and diagrammed. Built-in current and conductance models make the synaptic interpretation explicit.

Choose snnTorch for a direct route from conventional PyTorch training to spiking networks. Choose SNNLab when the structured circuit and its scientific observables are central to the experiment. Both have plotting tools; visualisation alone is not a unique SNNLab feature.

### Code style: SNNLab and snnTorch

Both snippets describe four input channels connected to sixteen current-based LIF neurons with exponential synaptic current. The SNNLab block authors the circuit; the snnTorch block also shows a short execution loop or simulation request. To run the SNNLab bundle, use the `simulate` pattern above.

**SNNLab**

```python
from snnlab import lang

net = lang.Network(
    "comparison",
    dt=0.1 * lang.ms,
)
inputs = net.input(
    "inputs",
    shape=("time", "batch", 4),
    signal_type="spikes",
    unit="spike",
)
cells = net.population(
    "E",
    size=16,
    neuron=lang.CUBA_LIF(tau_mem=20 * lang.ms),
)
net.connect(
    inputs,
    cells.excitatory,
    name="input_to_E",
    synapse=lang.ExponentialCurrent(tau=5 * lang.ms),
    weight=lang.Constant(1.0),
    initialization_scaling="direct",
)
net.output(
    "spikes",
    cells.spikes,
)
bundle = lang.compile(
    net,
    target="tools/snnsim",
)
```

**snnTorch**

```python
import math

import snntorch as snn
import torch
from torch import nn

projection = nn.Linear(
    in_features=4,
    out_features=16,
    bias=False,
)
nn.init.constant_(
    projection.weight,
    val=1.0,
)
cells = snn.Synaptic(
    alpha=math.exp(-0.1 / 5),
    beta=math.exp(-0.1 / 20),
)
synaptic_current, membrane_voltage = cells.init_synaptic()

inputs = torch.zeros((1000, 1, 4))  # time, batch, channels
inputs[::125] = 1
spikes = []

for input_spikes in inputs:
    current = projection(input_spikes)
    spike, synaptic_current, membrane_voltage = cells(
        current,
        synaptic_current,
        membrane_voltage,
    )
    spikes.append(spike)

spikes = torch.stack(spikes)
```

SNNLab declares a graph with named signals; snnTorch composes a PyTorch projection with a neuron module and carries state through the time loop. Its `alpha` and `beta` are per-step decay factors. See the [Synaptic API](https://snntorch.readthedocs.io/en/latest/snn.neurons_synaptic.html).

These examples illustrate API style, not numerical equivalence. Input generation, weight units, defaults, reset rules, delays and integration conventions differ; matching topology and time constants alone does not match spike trains.

## Brian 2

[Brian 2's model language](https://brian2.readthedocs.io/en/stable/user/models.html) lets researchers define differential equations, thresholds and reset rules directly. Its [equation system](https://brian2.readthedocs.io/en/stable/user/equations.html) includes dimensional checking, and its [execution machinery](https://brian2.readthedocs.io/en/stable/user/computation.html) supports generated code. This is a substantial modelling strength.

The distinction is what the languages describe. Brian's equations express the dynamics themselves; `snnlab.lang` expresses a circuit assembled from model specifications, with named signals and optional training recipes. SNNLab then executes the graph as a differentiable PyTorch module, allowing surrogate-gradient learning through its supported spiking dynamics.

Choose Brian when developing new equations or controlling numerical integration is the main task. Choose SNNLab when its built-in dynamics suit the experiment and you want an integrated authoring-to-training workflow. SNNLab supports [custom Python extensions](/custom-neurons-and-synapses), but `lang` is not a general equation parser or a replacement for Brian's modelling language.

**Brian 2**

```python
import brian2 as b2

b2.start_scope()
b2.defaultclock.dt = 0.1 * b2.ms

inputs = b2.PoissonGroup(
    4,
    rates=80 * b2.Hz,
)
cells = b2.NeuronGroup(
    16,
    model="""
        dv/dt = (-65*mV - v)/(20*ms) + I/(1*nF) : volt
        dI/dt = -I/(5*ms) : amp
    """,
    threshold="v > -50*mV",
    reset="v = -65*mV",
    method="exact",
)
cells.v = -65 * b2.mV

projection = b2.Synapses(
    inputs,
    cells,
    model="w : amp",
    on_pre="I_post += w",
)
projection.connect()
projection.w = 1 * b2.nA

spikes = b2.SpikeMonitor(cells)
b2.run(100 * b2.ms)
```

SNNLab selects built-in neuron and synapse specifications; Brian defines the voltage and current equations explicitly, then attaches a spike monitor. Here `v` is membrane voltage, `I` is synaptic current and `w` is the current increment per incoming spike. See Brian's [synapse syntax](https://brian2.readthedocs.io/en/stable/user/synapses.html).

These examples illustrate API style, not numerical equivalence. Input generation, weight units, defaults, reset rules, delays and integration conventions differ; matching topology and time constants alone does not match spike trains.

## NEST

[NEST](https://www.nest-simulator.org/) has an extensive neuron and synapse repertoire, including conductance models, AdEx, spike-timing-dependent plasticity and short-term plasticity. Its C++ kernel supports multicore and cluster execution, with Python commands for building networks and attaching recording devices.

SNNLab's opportunity is a different workflow: define the circuit in `lang`, train supported parameters through PyTorch, save learned weights and reuse the graph for inference. Constraints and named observations remain attached to the circuit description. This is useful for experiments that study how learning changes the dynamics of a recurrent network.

Choose NEST for large biological-network simulations or its established local plasticity models. SNNLab's built-in surrogate-gradient training is not equivalent to NEST's biological learning rules. A saved SNNLab graph is also not a NEST export; backend declarations do not imply cross-simulator execution.

**NEST**

```python
import nest

nest.ResetKernel()
nest.SetKernelStatus({"resolution": 0.1})  # ms

inputs = nest.Create(
    "poisson_generator",
    4,
    params={"rate": 80.0},  # Hz
)
cells = nest.Create(
    "iaf_psc_exp",
    16,
    params={
        "tau_m": 20.0,
        "tau_syn_ex": 5.0,
        "C_m": 1000.0,
        "E_L": -65.0,
        "V_m": -65.0,
        "V_reset": -65.0,
        "V_th": -50.0,
    },
)
nest.Connect(
    inputs,
    cells,
    conn_spec="all_to_all",
    syn_spec={
        "weight": 1000.0,  # pA
        "delay": 0.1,  # ms
    },
)

spikes = nest.Create("spike_recorder")
nest.Connect(
    cells,
    spikes,
)
nest.Simulate(100.0)  # ms
```

SNNLab compiles the circuit into a reusable bundle; NEST creates objects in its simulation kernel and connects a recording device. This NEST example uses milliseconds, picoamperes and picofarads; each Poisson generator supplies independent spike trains to its targets. See the [iaf_psc_exp model](https://nest-simulator.readthedocs.io/en/stable/models/iaf_psc_exp.html) and [Poisson generator](https://nest-simulator.readthedocs.io/en/stable/models/poisson_generator.html).

These examples illustrate API style, not numerical equivalence. Input generation, weight units, defaults, reset rules, delays and integration conventions differ; matching topology and time constants alone does not match spike trains.

## Where SNNLab fits

SNNLab is a good fit when you want to **describe a circuit once, inspect it, train it and analyse its activity using the same named structure**. Its strengths are the combination of explicit current/conductance dynamics, declarative authoring, saved graph contracts and integrated experimental outputs.

Other libraries offer broader model catalogues, dataset ecosystems, equation languages or established large-scale execution. We aim to make SNNLab's particular workflow clear and useful, while leaving those trade-offs visible. Start with [Quickstart](/quickstart), then explore [Training](/training), [PyTorch Integration](/pytorch-integration) and the [Lang API](/api/lang#constructor).
