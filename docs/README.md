# snnlab documentation

Fumadocs + Astro static documentation with KaTeX and browser-side search. Requires Bun 1.4.2 or newer.

```sh
bun install --frozen-lockfile
bun run dev
```

The development server defaults to `http://localhost:3001`. Static preview also uses port 3001.

The site contains Installation, Quickstart, Training, Inference, PyTorch Integration, a collapsible API Reference section and Changelog. `/` redirects to `/installation`; both trailing-slash forms work. Cloudflare redirects previous `/docs/` links to the new paths.

Edit Installation in `content/docs/` and keep navigation in `content/docs/meta.json`. Changelog is generated from the root `CHANGELOG.md` before development, type checks and builds; edit that source file.

```sh
bun run types:check
bun run build
bun run preview
```

The build exports plain HTML, CSS, JavaScript, search data, and KaTeX fonts into `out/`. Astro uses `output: static`; no application server is needed. Markdown downloads use explicit `/llms.mdx/docs/.../content.md` routes; runtime content-negotiation rewrites are unavailable on static hosts.

## GitHub Pages

`.github/workflows/docs.yml` checks and builds docs on pull requests and deploys `main` through GitHub Pages Actions. The GitHub build sets `SITE_BASE_PATH=/snnlab` and `SITE_URL=https://eoinmurray.github.io/snnlab/`.

## Cloudflare

`wrangler.jsonc` deploys the root-path static export as Workers Static Assets at `ssnlab.eoinmurray.info`. Bun runs Wrangler through `bunx`; Cloudflare authentication is required.

```sh
SITE_URL=https://ssnlab.eoinmurray.info bun run deploy:cloudflare
```

Cloudflare deployments are manual through Wrangler. GitHub Pages updates automatically from `main`. Never deploy a build made with `/snnlab` as its base path to the custom-domain root.

`astro.config.mjs` configures remark-math and rehype-katex. Commit `bun.lock`; `.astro/`, `out/`, and `node_modules/` are generated and ignored.

Quickstart prose lives in `scripts/quickstart.mdx`; its script and generated PNGs live in `../examples/quickstart/`. Run the Python script after changing it. `scripts/sync-quickstart.ts` publishes the complete script and copies its images and download before development, checks and builds.

Quickstart, Training and Inference are generated from their source templates in `scripts/` and Python examples in `../examples/`. Run the corresponding example script to regenerate plots, then use the Bun check/build commands to synchronize downloadable scripts and figures.

Inference follows Training in navigation; PyTorch Integration follows Inference. Its source template is `scripts/inference.mdx` and its runnable script is `../examples/inference/inference.py`; `scripts/sync-inference.ts` copies the generated diagram, response figure and script into `public/inference/`. Run Training first, then Inference: the latter reads the sibling Training bundle and checkpoint without modifying them.

PyTorch Integration is generated by `scripts/sync-pytorch.ts` from `scripts/pytorch-integration.mdx` and `../examples/pytorch/training.py`. It reuses the Training bundle with an external PyTorch loop; its trained state dictionary and metrics are generated locally and excluded from source distributions.

API Reference is grouped into collapsible Lang, Sim and Viz sections. Lang covers authoring, components, parameters, training recipes, compilation and operations/readouts. Sim covers ExecutionSpec (including input bindings), execution results and PyTorch integration. Viz covers diagrams, plotting and animation. Previous `/api/network`, `/api/inputs`, `/api/execution-spec` and `/api/connect` routes redirect to their grouped references.

Input declarations live in Network; binding types and compatibility rules live in ExecutionSpec. Both former Inputs routes redirect to ExecutionSpec.

Current-based LIF follows PyTorch Integration and demonstrates built-in current neurons and synapses. `scripts/sync-current-lif.ts` publishes its script and figures from `../examples/current-lif/`.

Customisation follows Current-based LIF and demonstrates current-based LIF neurons, registered adaptive dynamics and a custom initializer. `scripts/sync-customisation.ts` publishes the script and figures; run `../examples/customisation/customisation.py` to regenerate outputs.
