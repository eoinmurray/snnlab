Building on [Current-based LIF](/current-lif), this example asks a simple question: **how does spike-triggered adaptation change a neuron's response to sustained input?** Four input channels drive two populations of eight cells with exactly the same weights and registered exponential current synapses. One uses the built-in `CUBA_LIF`; the other uses a registered Python neuron definition that builds an opposing current after each spike. Both custom updates operate on whole tensors, preserve state dtype and can compile without a decorator.

![Four input channels connect through exponential current synapses to standard and adaptive populations, each with eight cells and its own spike output.](/customisation/network.png)

The stimulus starts at 20 Hz, rises to 120 Hz between 100 and 400 ms, then returns to 20 Hz. The custom population's adaptation builds up during stimulation and decays afterwards. This is an illustrative discrete-time adaptive model; it is not a claim that one parameterization describes every biological neuron.

Run from the repository root:

```bash
uv run python examples/customisation/customisation.py
uv run python examples/customisation/customisation.py --simulate
uv run python examples/customisation/customisation.py --simulate --eager --extension-validation strict
```

The first command builds and saves `network.bundle`, `network.png`, `customisation.png` and `metrics.json` beside itself. The second starts a fresh process, loads the saved bundle and regenerates the same seeded stimulus without registering definitions or rebuilding the network. The third selects eager execution and strict callback value checks for debugging. Keep `custom_neurons.py` beside the script so its callbacks are importable. A missing bundle raises `FileNotFoundError`; a missing callback module raises a descriptive error. Graphviz's `dot` executable is needed for the diagram. In a headless environment you can set `MPLBACKEND=Agg` when running the script.

The default device is CPU. Use `--simulate --device cuda:0` on a CUDA host;
that option changes execution placement without changing the fixed CPU-generated
stimulus. This small plotting example is not a throughput benchmark. The

## 1. Define the custom neuron

A custom neuron has an initial tensor state and a step function. Put these functions in `custom_neurons.py`, an importable module outside the bundle. The step receives previous state, excitatory and inhibitory input, timestep, configuration and a spike function compatible with the run's surrogate gradient.

```python
{{NEURON}}
```

The initial state provides voltage and adaptation. The executor adds a zero-valued integer refractory tensor when absent. The step returns the updated state and binary spikes. Here adaptation subtracts from the net current and increases by `adaptation_na` after each spike; its exponential decay is controlled by `tau_adapt_ms`.

The ordinary `adaptive_step(context)` compiles by default alongside the built-in neuron update. Its PyTorch expressions operate on the whole batch/population; `torch.where` broadcasts a scalar reset without a Python branch or a full-sized reset allocation. Incoming currents are converted to the voltage state's dtype so BF16 matrix products do not change the recurrent state contract. The exponential factors depend only on fixed configuration and can specialize during tracing. Configuration validation runs before updates. Keep state keys/shapes/devices/dtypes stable, use `context.spike` for gradients, and avoid `.item()`, `.cpu()`, NumPy conversions or loops over cells inside the step. No compilation decorator is required.

`state_units` makes adaptation available through `population.state("adaptation")`. For callback contracts and additional extension categories, see [Extensions](/api/lang/extensions).

The executor supplies `drive` after delay routing and weight projection. The
callback filters that current with the same 5 ms exponential recurrence as the
built-in `ExponentialCurrent`; it does not multiply weights again. Its state is
one `(batch, cells)` tensor allocated on the requested device/dtype. Casting the
drive to the previous state's dtype preserves that state under autocast. The
step returns new tensors and a new mapping, leaving previous state untouched.

Both populations use this same synapse implementation and the same parameter,
so the comparison still isolates neuron adaptation.

The initializer receives the runtime shape, configuration, device and dtype. It draws normal values and clips them at a configurable minimum. With the default initialization scaling, projection initialization subsequently divides by fan-in, and then applies the declared constraint. Keep this function in `custom_neurons.py` too.

This initializer draws the whole weight tensor on the requested device with the requested dtype. Initialization runs eagerly during setup to preserve seeded draws; speeding up per-timestep dynamics is separate. Repeated custom weight constraints compile after optimizer updates. Prefer whole-tensor expressions such as `parameter.clamp(...)` to loops over weights; see [Weights](/weights#efficient-custom-initializers-and-constraints).

Registration assigns stable, versioned names. The bundle stores those names, import references, units and configuration. Each process loads the referenced module automatically; the module does not need to register itself. For installed extensions, declare `package="distribution-name"` to record and check its exact installed version. Change the versioned definition name when its semantics change.

The neuron and synapse registrations declare `capture_safe=True`: their
initializers are deterministic allocations, and their updates have no random
draws, host reads or Python side effects. This permits eligible CUDA replay;
it does not itself enable replay or compiled timestep blocks. The random weight
initializer runs once during setup and remains outside capture. Keep strict
validation for development; structural validation is the execution default.

`DenseArrayBinding` supplies the custom stimulus. The shared parameter has graph shape `(8, 4)` and unit `"nA"`; both projections reference it, so differences in response come from neuron dynamics. `CustomSynapse("example.exponential_current/v1", tau_ms=5.0)` adds incoming spike-weighted current and lets it decay with a 5 ms time constant. Inhibitory current projections would subtract from membrane drive.

The standard neuron uses the new [CUBA_LIF](/api/lang/components#current-based-lif), and the adaptive population uses `CustomNeuron`. Both expect current input. Mixing these with a conductance synapse is rejected rather than silently interpreting incompatible units.

The graph and manifest list required extension names and callback references. `lang.load_bundle` and the simulator resolve these references automatically from modules available in the current environment. The graph digest covers the implementation references; Python source and pickled functions are never saved in the bundle. Additional custom state is included in runtime continuation artifacts, so splitting an execution does not reset adaptation or synaptic history.

`Performance()` retains automatic compilation, precision and replay policies.
This example selects eager execution only with `--eager`. Custom neurons and
synapses currently use the individual compiled-kernel loop; they do not use
compiled timestep blocks even when marked capture-safe. The single CPU
simulation does not replay a CUDA Graph. Eligible repeated CUDA shapes can
replay, and the registrations above permit that path. See
`metrics.json` → `performance` for requested settings, selected paths and fallback
reasons. Exposed diagnostic histories are retained for the plots and add work.
